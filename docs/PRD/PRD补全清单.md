# PRD 补全清单（阶段 0）

> 对照《技术栈手册》第二节七类信息与 PRD 模板逐项检查 Agent造物坊 PRD V0.1 的结果。

## 必须问（本轮 3 个）

> ✅ 已全部关闭（产品经理按推荐）：Q1=C 先本地后迁云；Q2=B 工厂出脚本、产品经理自部署；Q3=C MVP 用 mock、真实 Key 验收前填。

### 问题 1：工厂流水线（AI 执行、写代码、测试）跑在哪里？
- 为什么重要：决定整个产品是"本地桌面工具"还是"中心云端服务"，直接改变架构、成本和多租户隔离的可行性。
- 选项：A 纯本地（桌面应用内置 AI 执行，在用户电脑上跑）；B 桌面应用 + 中心云后端（流水线在云端跑，桌面只是操作台）；C 先本地跑通，对外阶段再迁中心云
- 推荐：**C**——MVP 阶段先本地跑通一条线（成本低、不碰多租户），终态对外时再上中心云。
- 不选的后果：选 A 纯本地做不了"对外 + 多租户隔离"；选 B 一开始就要搭中心云 + 计费 + 隔离，拖慢 MVP。
- （可以只回复"按推荐"）

### 问题 2：生产出来的产品"上线部署"谁来做、云费用谁出？
- 为什么重要：涉及计费云资源，必须定清工厂责任边界和钱从哪来。
- 选项：A 工厂代部署到工厂云、产品经理付云费；B 工厂只产出代码 + 一键部署脚本 + 验收清单，产品经理用自己的云账号部署；C MVP 先只产出"可本地运行的产品"，部署整体后置
- 推荐：**B 起步**——边界最清晰、成本最可控，也符合"产品经理自带 Key"的定位。
- 不选的后果：选 A 工厂要承担多租户云资源管理和计费风险；选 C 则"完整可上线"目标（Q3=A）在 MVP 阶段打折扣。

### 问题 3：产品经理"自带 API Key"的范围到哪？
- 为什么重要：决定成本结构，以及工厂是否要碰真金白银。
- 选项：A 生产环节（写代码那个 AI）和产品运行时（生产出的产品自己用模型）都用产品经理自己的 Key；B 生产环节用工厂统一 Key、产品运行时用产品经理 Key；C MVP 阶段先用 mock 验证流程不花钱，真实 Key 验收前再填
- 推荐：**C**——MVP 阶段零真钱成本，验证流程稳定性，真实模型冒烟时再填 Key。
- 不选的后果：过早引入真实付费调用，MVP 验证成本不可控。

## 已发现的矛盾（如有）

- **"桌面应用（本地）" vs "对外产品 + 多租户隔离（云端）"**：桌面应用天然偏本地，而对外多租户要求数据在云端隔离。这不是硬矛盾（可做"桌面操作台 + 中心云"），但必须由必须问 1 定方向，否则架构会摇摆。
- **PRD 字段 2"产物含部署 + 账号隔离" vs Q10"MVP 只跑通一条线（内部）"**：账号隔离和部署属于对外阶段的完整目标，MVP 阶段暂不包含。建议 PRD 明确：MVP 交付"可本地运行 + 一键部署脚本"，账号隔离后置。
