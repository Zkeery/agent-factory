# 第 6 阶段技术开发文档｜做实代码生成：产出能本地跑的最小 AI 应用

> 配套文档：《Agent造物坊 PRD V1.0》、第 1-5 阶段技术开发文档。
> 本文档只覆盖第 6 子阶段（做实代码生成）。不提前实现后续能力。

## 一、阶段目标

把工厂「构建」环节从"骨架占位"升级为**能本地跑的最小可运行 AI 应用**：产品经理给想法，工厂生成的代码装依赖、配 Key、一条命令就能跑起来一个能用的 AI 应用（输入 → 调模型 → 输出）。

## 二、技术适配摘要

- 沿用现有技术栈；生成的产品形态统一为「FastAPI 单文件 + requirements.txt + README」。
- 模型调用：生成的产品用 openai 兼容接口（读环境变量 API Key），与工厂自身一致。
- 测试工序适配：语法检查 + 可 import + 依赖文件存在。

## 三、技术栈与模型

- 工厂不变；生成的产品：FastAPI + uvicorn + openai（DeepSeek 兼容）。

## 四、环境与配置

- 生成的产品读 `DEEPSEEK_API_KEY`（或 `LLM_API_KEY`）环境变量；无 Key 时可返回明确错误，不崩溃。

## 五、项目结构

生成的产品目录（`data/code/<run_id>/`）：

```text
<run_id>/
├── app.py           # FastAPI 应用：一个核心接口，接收输入，调模型，返回结果
├── requirements.txt # fastapi、uvicorn、openai
├── README.md        # 怎么跑、怎么配 Key、接口说明
└── deploy/
    └── start.sh     # pip install + uvicorn 启动（部署工序生成）
```

## 六、数据、资产与状态

- 无状态机变化；BUILDING 阶段从"写一个 app.py"改为"写 app.py + requirements.txt + README.md"。

## 七、API / 工具设计

生成的产品对外提供一个核心接口（由 prompt 根据想法设计，统一约定）：

- `POST /generate`：请求 `{"input": "..."}` → 响应 `{"result": "..."}`（结构由模型生成并自洽）
- 工厂测试工序不依赖具体接口细节，只验证「可 import + 语法正确 + 依赖文件存在」。

## 八、Prompt 设计（核心改动）

- `prompts/code.md` 重写：输入想法 + PRD，输出**完整 FastAPI 应用**（app.py 代码）+ requirements.txt 内容 + README 内容，用分隔标记分块，便于工厂拆分落盘。
- 约束：
  - app.py 必须是完整可运行 FastAPI 应用，含 `POST /generate` 接口、模型调用、错误处理（无 Key 返回明确错误）；
  - 模型调用读环境变量，不硬编码 Key；
  - 代码有结构校验（前端已有解析器可复用思路），分块解析失败有限重试。

## 九、验收界面或纵向切片

- 工厂验收界面「证据包」展示生成的 app.py / requirements.txt / README（沿用现有 evidence 机制）。

## 十、测试要求

- 第一层 mock 测试：
  1. BUILDING 后生成 app.py + requirements.txt + README.md 三个文件且非空。
  2. 生成的 app.py 通过 py_compile 语法检查。
  3. 生成的 app.py 可 import（工厂测试进程内 import 一次）。
  4. requirements.txt 包含 fastapi/uvicorn/openai。
  5. 回归：第 1-5 阶段测试保持通过。
- 第二层真实冒烟：用真实 DeepSeek 生成一个产品，本地 pip install + uvicorn 起服务，curl 调 `/generate` 得到真实模型结果，记录。

## 十一、验收清单（产品经理照着做）

- [ ] 工厂生成的产品目录里有 app.py / requirements.txt / README.md / deploy/start.sh
- [ ] 照着 README 装依赖、配 Key、启动，能调通接口拿到结果

## 十二、风险与待确认项

- 生成的产品代码质量依赖模型，结构校验保证「能跑」，不保证「业务完美」；质量以三维打分（代码骨架维度）衡量。
- 生成的产品无前端（API 优先），完整前端后续阶段再做。
- 必须由产品经理决定的问题：无。

## 十三、交接给下一阶段

- 就绪：工厂能产出「能本地跑的最小 AI 应用」，代码环节不再是占位。
- 下一阶段：可考虑给生成的产品补极简前端，或进入阶段 4 上线准备。
