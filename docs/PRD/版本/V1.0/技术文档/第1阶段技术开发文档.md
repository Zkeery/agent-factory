# 第 1 阶段技术开发文档｜工厂内核：最小流水线闭环

> 配套文档：《Agent造物坊 PRD V0.1》、《技术适配声明》、AI Agent 产品 Vibe Coding 通用技术栈手册。
> 本文档只覆盖第 1 阶段（阶段 2 后端 MVP 的第一个子阶段）。AI 开发时不得提前实现其他阶段的能力。

## 一、阶段目标

- **交付范围（对齐 PRD Q10）**：工厂内核——把"产品经理给想法"到"通过闸门交证据包"的**固定工序闭环**用代码跑通。核心是验证工厂的骨架（阶段状态机 + 闸门 + 人工确认 + 持久化 + 证据包 + mock 模型）能稳定运转。
- **阶段产物**：
  1. 流水线引擎（阶段状态机 + 闸门检查）
  2. 最小工序闭环（想法 → 澄清决策卡 → 回答 → PRD 草稿 → 确认 → 代码骨架 → mock 测试 → 证据包 → 闸门）
  3. SQLite 持久化（重启可恢复）
  4. 临时验收界面（单个 HTML，SSE 进度）
  5. mock 模型（离线、零真钱成本）
- **验收标准**：产品经理能在临时界面走完"给想法 → 回答决策卡 → 确认 PRD → 看到证据包 → 闸门通过"的全流程；后端 mock 测试全绿；重启后任务状态可恢复。
- **明确不做**：真实模型调用（待 Key）、真实代码生成（mock 占位）、正式前端、桌面应用（Electron）、多租户隔离、真实部署、自主 Agent 类产品。
- **本阶段打通的主链路片段**：`提交想法 → 澄清(决策卡) → 人工回答 → PRD 草稿 → 人工确认 → 代码骨架(mock) → 测试(mock) → 证据包 → 闸门通过`。

## 二、技术适配摘要

- 引用《技术适配声明》结论：工厂 = Agent Harness，后端先行，MVP 本地单进程，mock 先行。
- 本阶段采用默认方案：Python 3.12 + FastAPI + Pydantic + pytest + Git。
- 本阶段启用按需模块：SQLite + SQLAlchemy（多实体持久化）、SSE（进度流）、后台执行（长流程）、文件系统（代码/证据产物）、子进程（测试运行）。
- 本阶段偏离/暂缓：正式前端暂缓（用临时验收界面单 HTML）；真实模型暂缓（用 mock）；Electron/中心云/多租户暂缓。
- 开发路径：**后端先行 + 最小验收界面**（工厂核心是分阶段确认交互，仅靠 Swagger 无法判断"流程对不对"，故配单 HTML 临时验收界面）。

## 三、技术栈与模型

| 组件 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Python 3.12 + FastAPI | 手册默认 |
| 校验 | Pydantic | 接口与模型结构化输出 |
| ORM | SQLAlchemy + Alembic | 多实体持久化 |
| 数据库 | SQLite | 本地 MVP |
| 测试 | pytest | mock 自动化 |
| 模型 | 本阶段不接入真实模型 | `MockLLM` 占位；真实模型接口留好，验收前替换 |
| 任务队列 | 不引入 | 单进程 + 后台线程即可 |

## 四、环境与配置

- 配置项（不含秘密）：数据库路径、端口、mock 开关。`backend/.env.example` 提供 `DATABASE_URL`、`PORT=8010`、`LLM_PROVIDER=mock`。
- 需要用户提供：无（本阶段零 Key）；真实模型 Key 验收前再提供。
- 启动：`cd backend && .venv/bin/uvicorn app.main:app --port 8010`；验收界面 `http://127.0.0.1:8010/`。
- 依赖：Python 3.12 `.venv`，`pip install -r requirements.txt`。

## 六、数据、资产与状态

- 持久化：SQLite（多实体、事务、重启可恢复）。
- 表（schema v1）：

| 表 | 字段要点 | 说明 |
| --- | --- | --- |
| `factory_runs` | id, idea(原文), status, current_stage, created_at, updated_at | 一次造物运行 |
| `stage_events` | id, run_id, stage, event_type, payload, created_at | 阶段流转事件（含 SSE 回放源） |
| `decisions` | id, run_id, code, question, options, recommendation, answer, status, created_at | 决策卡 + 台账 |
| `confirmations` | id, run_id, kind, status, created_at | 人工确认点（PRD 确认等） |
| `evidence_items` | id, run_id, stage, title, content_path, created_at | 证据包条目 |

- 状态机（本阶段最小工序）：

```text
idea_submitted → clarifying → awaiting_answers → prd_drafting
→ awaiting_prd_confirm → building → testing → evidence_ready
→ gate_passed / gate_failed
```

- 状态流转由确定性代码控制（固定流程，不允许模型自主跳转）；每个状态进入时写 `stage_events`，SSE 从此回放。
- 兼容策略：schema v1 起步，后续新增状态不破坏已有字段。

## 七、API / 工具设计

统一错误：`{"error":{"code","message"}}`；长流程用「提交 + SSE 进度 + 查询状态」。

| 方法 | 路径 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/api/v1/runs` | `{idea}` | `{run_id, status, current_stage}` | 提交想法，启动流水线 |
| GET | `/api/v1/runs/{id}` | - | 运行状态 + 阶段 + 决策卡 + 证据摘要 | 查询 |
| GET | `/api/v1/runs/{id}/events` | - | SSE 流 | 事件序列：`chunk` × N → `done` 或 `error` |
| POST | `/api/v1/runs/{id}/decisions/{code}/answer` | `{answer}` | 更新后的决策卡 | 产品经理回答决策卡 |
| POST | `/api/v1/runs/{id}/confirm-prd` | `{confirmed: true}` | 更新状态 | PRD 人工确认 |
| GET | `/api/v1/runs/{id}/evidence` | - | 证据包条目列表 | 查看证据 |

- SSE 约定：`chunk` 零到多次 → 以 `done`（含完整结果）或 `error`（统一错误结构）收尾，二者必居其一。
- 工具（引擎内部，不对外）：`write_file`（写代码/证据）、`run_tests`（子进程跑 mock 测试）、`mock_generate`（mock 模型）。第 1 阶段工具由确定性代码调用，不开放给模型自主选工具。

## 八、Prompt 设计

本阶段 mock 阶段先定结构，真实模型接入后沿用（Prompt 独立于代码）。

- `prompts/clarify.md`：输入想法 → 输出 ≤5 个"必须问"决策卡（JSON）。约束：每卡含 question/options/recommendation/consequence；禁止超 5 个。
- `prompts/prd.md`：输入想法 + 决策卡结论 → 输出 PRD 草稿（8 字段）。
- 解析：模型输出 JSON → Pydantic 强校验；校验失败有限重试（≤2 次），仍失败走统一错误。数量约束超限（如决策卡 >5）记为瑕疵，不反复重试。

## 九、验收界面或纵向切片

- 本阶段需要**临时验收界面**（单 HTML `static/index.html`，原生 JS + fetch + SSE）：
  - 输入想法 → 提交 → 看进度条/阶段流转 → 回答决策卡 → 确认 PRD → 查看证据包 → 看到"闸门通过"。
- 功能上限：只做判断"流程对不对"必需的交互，不做视觉、账号、多终端。

## 十、测试要求

- 第一层 mock 测试（pytest，逐条）：
  1. 状态机：合法流转通过、非法流转被拒（如未回答决策卡不能进 PRD）。
  2. 闸门：决策卡未全答 → 澄清闸门不通过；PRD 未确认 → PRD 闸门不通过。
  3. 决策卡：生成数量 ≤5、结构校验、回答持久化。
  4. 错误路径：非法 run_id、非法决策卡 code、重复回答。
  5. 恢复：写入中途"杀进程"，重启后 `factory_runs` 状态与事件完整可续。
  6. SSE：事件序列以 `done` 或 `error` 收尾；SDK/引擎层异常也走 `error` 结构。
  7. 文件安全：写文件路径限制在本项目 `data/` 内（防路径遍历）。
- 第二层真实冒烟：本阶段**无**（纯 mock 工程阶段，待 Key 后在后续子阶段做真实模型冒烟，如实标注）。

## 十二、风险与待确认项

- 已知限制：本阶段是 mock 闭环，**不代表真实模型质量**；代码骨架是占位模板，非真实产品代码。
- 成本：零真钱成本。
- 安全：写文件限定 `data/` 内；无密钥；无外部发送。
- 必须由产品经理决定的问题：无。
