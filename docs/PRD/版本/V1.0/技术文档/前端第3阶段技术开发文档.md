# 第 3 阶段前端开发文档｜任务中心 + 刷新恢复 + 失败重试

> 配套文档：《前端技术适配声明》、前端第 1/2 阶段技术开发文档、后端第 1-4 阶段文档。
> 本文档只覆盖前端子阶段 3。不提前实现子阶段 4（质量与发布准备）能力。

## 1. 本阶段目标

产品经理能看到**所有生产过的产品**（任务列表），刷新页面或换设备能**找回正在进行的任务**，失败的任务能**一键重试**。

## 2. 范围

### 本阶段包含
- 后端新增：`GET /runs` 列表接口（返回所有 run 摘要，按时间倒序）
- 前端任务列表：任务卡片（想法、状态、时间），点击可查看/恢复
- 刷新恢复：localStorage 记住当前 run_id，刷新后自动恢复
- 失败重试：failed/gate_failed 任务显示「用相同想法重试」按钮

### 本阶段不包含
- 取消进行中的任务（用"重新提交"代替，MVP 不做取消状态机）
- 登录、Electron、完整视觉（后续）

## 3. 用户流程
1. 打开首页，看到「任务列表」（历史 + 当前）
2. 提交新想法 → 新任务出现在列表顶部
3. 点击某个任务 → 恢复查看它的进度/决策卡/PRD/证据
4. 刷新页面 → 自动恢复上次正在进行的任务
5. 失败任务 → 点「重试」→ 用相同想法重新提交

## 4. 页面状态矩阵

| 模块 | 初始 | 空 | 有任务 | 失败 |
|---|---|---|---|---|
| 任务列表 | 显示列表 | "暂无任务" | 卡片列表 | 失败卡片标红 + 重试按钮 |
| 当前任务区 | 隐藏 | - | 显示进度/决策卡等 | 失败原因 + 重试 |
| 度量区 | 显示 | 全 0 | 显示数字 | - |

## 5. 接口契约

新增 `GET /api/v1/runs`：

- 请求：无
- 成功返回：`{"runs":[{"id","idea","current_stage","status","created_at"}]}`（倒序）
- 错误：统一 `{"error":{"code","message"}}`

其余接口沿用（runs/{id}、decisions、confirm-prd、evidence、score、metrics、events）。

## 6. 实现方案
- 后端：`runs.py` 加列表路由，返回摘要（不加载全部 decisions/evidence，控制响应大小）。
- 前端 hook：加 `useRunList`（拉取列表）；`useFactoryRun` 加「恢复 run_id」与「重试」能力。
- 刷新恢复：提交成功时 localStorage 存 run_id；页面挂载时若有存留且任务未终态，自动恢复。
- 重试：记录原想法，点重试 = 用原想法调 `createRun` 重新提交（新 run_id）。
- 状态映射复用第 1/2 阶段的 STAGE_CN。

## 7. 验收标准
- Given 提交多个想法 / When 打开首页 / Then 任务列表按时间倒序显示。
- Given 有进行中任务 / When 刷新页面 / Then 自动恢复该任务并继续收 SSE。
- Given 一个失败任务 / When 点「重试」/ Then 用相同想法重新提交并进入流水线。
- 自动检查：单测 + E2E（列表、恢复、重试）+ 类型/Lint/构建全通过。
- E2E 更新：保留完整闭环用例，新增「任务列表出现新任务」「失败重试」用例。

## 8. 风险与回退
- 风险：localStorage 恢复的 run 已终态，恢复后不重连 SSE；降级：恢复时先拉状态，终态则只展示不重连。
- 回退：后端仅加只读列表接口，前端加列表组件，回退移除即可。
