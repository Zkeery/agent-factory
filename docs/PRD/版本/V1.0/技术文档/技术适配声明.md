# 技术适配声明 · Agent造物坊

> 阶段 1 产出。本声明基于 PRD V0.1、共享技术栈手册（一至六节）、多项目开发指南与 Agent Blueprint（BLUEPRINT.md）方法论推导。
> **推导方式**：本产品本身是 Agent 产品，需要架构推导；当前项目未配置 `.env.blueprint` 模型接口，因此由**当前 AI 按手册分析，未运行 blueprint 程序管线**。架构结论引用了 blueprint 的七层架构与 17 组件选型方法论，但未伪造程序阶段或独立模型审稿。

## 1. 产品形态判断

- **产品类型与核心任务**：Agent造物坊是一个 **Agent 产品工厂**——用一套可复用的 AI 约束流程（阶段、闸门、证据包），把产品经理的想法稳定做成可上线产品。它本身就是一个 Agent 产品（工厂 = 编排 AI 干活的 Harness），不是普通的一次性生成工具。
- **核心交互**：**分阶段确认**。产品经理只做三件事：回答业务判断问题、看证据、打分数；AI 按固定工序推进并交证据，高风险动作人工确认。
- **开发路径**：**后端先行**。流水线引擎（约束流程 + 闸门 + 证据包 + 工具分发）是核心价值，先把它做成可独立验证的能力；界面是"操作台"，后置。
- **当前阶段范围**：阶段 2 后端 MVP 的第一条纵向链路——「产品经理给想法 → 工厂按固定工序驱动 AI 生产一款固定流程 AI 应用 → 交证据 → 通过闸门」。MVP 阶段先本地跑通（决策：流水线先本地后迁云）。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI | 手册默认后端基线；工厂引擎用 API 驱动、可测试 |
| Pydantic | 校验接口与模型结构化输出（决策卡、PRD、证据包结构） |
| pytest | 闸门检查、流程状态机、工具分发的自动化测试 |
| Git | 强制底线；工厂产出的每个产品代码用 Git 管理、可回滚 |
| SQLite + SQLAlchemy + Alembic | 工厂要持久化项目状态、决策台账、任务/阶段状态、证据包，多实体关系且需事务 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 当前阶段是否引入 |
| --- | --- | --- |
| 持久化任务记录 + 后台执行 | 生产一款产品是长流程（多阶段、多步骤），进程重启要能恢复 | 是（阶段 2 核心） |
| SSE | 产品经理要看进度（阶段流转、闸门结果） | 是（阶段 2 核心） |
| 文件系统（生成代码目录） | 工厂产物是代码 + 文档 + 证据 | 是 |
| 子进程执行（命令/测试） | 工厂要跑测试、构建、部署脚本 | 是 |
| 蓝图引擎（plan/audit） | 阶段 1 架构推导、迭代审计 | 架构方法论已引用；程序管线待配置模型后启用 |
| 任务队列（Redis/Celery） | 仅当并发生产多款产品、后台任务量超阈值 | 否（MVP 单进程 + 线程即可） |
| 对象存储 | 大文件产物 | 否（产物是代码/文本，本地目录够用） |
| Chroma/RAG | 知识库检索 | 否（规则/手册数量有限，直接内嵌为知识） |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代/暂缓 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| 正式前端（Next.js） | MVP 用**临时验收界面**（单个 HTML 挂在 FastAPI `static/`） | Q10 定 MVP 只跑通流水线一条线，核心价值未验证前不铺正式前端 | 产品经理通过临时界面看进度/交证据 | 核心链路验证通过后，阶段 3 做正式前端 |
| 桌面应用（Electron） | 暂缓，先做 Web/本地 API 形态 | Q2 定桌面为终态，但流水线先本地跑通；Electron 是外壳，不决定流水线成立与否 | 终态"桌面应用"延后到第二步 | 流水线稳定后套 Electron 外壳 |
| 多租户隔离 + 对外账号 | 暂缓 | Q1/Q10 定 MVP 先内部单用户，对外阶段再上 | MVP 单用户，无隔离需求 | 进入对外阶段前 |
| 中心云部署 | MVP 本地单进程 | Q1=C 先本地后迁云 | 数据在本地，部署形态简单 | 对外阶段迁中心云 + 多租户 |
| 自主 Agent 类产品支持 | 暂缓 | Q4 定类型不限，但先固定流程跑通 | MVP 只覆盖固定流程 AI 应用 | 固定流程稳定后扩展 |

## 5. 强制底线检查

- **密钥与隐私**：通过（设计）——产品经理 Key 存本项目 `.env`，不进仓库/前端/日志；流水线写入范围限定当前产品项目目录。
- **数据与任务可恢复**：通过（设计）——项目状态、决策台账、任务/阶段状态持久化到 SQLite，进程重启可恢复；阶段 2 实现后实测。
- **输入输出校验**：通过（设计）——PRD 输入校验、模型结构化输出（决策卡/证据包）校验、上传安全文件名。
- **错误与日志边界**：通过（设计）——接口统一返回 `{"error":{"code","message"}}`，不泄露堆栈；SSE 以 `done`/`error` 收尾。
- **测试与真实模型验收**：计划——mock 自动化测试先行验证流程；真实模型冒烟待产品经理填 Key 后执行（MVP 阶段零真钱成本）。

## 6. 需要产品经理决定的问题

- 无。决策台账（D1–D10）已无影响本阶段的待定项。

## 附：Agent 架构推导（blueprint 方法论，当前 AI 分析）

### Harness 五要素（工厂的领域骨架）

| 槽位 | 内容 |
| --- | --- |
| 工具 | 文件读写、Shell 执行、Git、测试运行、部署脚本生成、蓝图 plan/audit |
| 知识 | AGENTS.md 规则、三份手册、PRD 模板、蓝图 BLUEPRINT、项目模板 |
| 观察 | git diff、测试结果、日志、阶段状态、闸门检查结果 |
| 行动 | CLI 命令、API 调用、生成代码/文档、执行部署脚本 |
| 权限 | 高风险/付费/对外动作人工确认、密钥不进日志、写入范围限定当前项目 |

### 七层架构

| 层 | 名称 | Agent造物坊落点 |
| --- | --- | --- |
| ① | 交互层 | 操作台：MVP=临时验收界面（SSE 进度），终态=桌面 Electron |
| ② | 产品层 | 工厂外壳：项目管理、流程状态、证据包、决策台账、会话 |
| ③ | Agent 编排层 | **流水线引擎**：阶段状态机 + 闸门检查 + 工具分发 + 权限审批 + 记忆 + 任务持久化（核心） |
| ④ | 模型层 | 产品经理自带 Key 的主模型 + 结构化输出校验 + 超时/重试/失败降级 |
| ⑤ | 能力集成层 | 工具集（文件/命令/git/测试/部署脚本）+ 蓝图引擎（架构推导/审计） |
| ⑥ | 数据层 | 项目状态、决策台账、任务/阶段状态、证据包、生成的代码、日志 |
| ⑦ | 基础设施层 | MVP：本地单进程；终态：中心云 + 多租户隔离 |

### 组件选型（blueprint 17 组件，只选需要的）

| 组件 | 是否选 | 理由 |
| --- | --- | --- |
| s01 Agent Loop | ✅ 必选 | 一切基础，驱动 AI 循环干活 |
| s02 工具系统 | ✅ 必选 | 文件/命令/git/测试等外部动作 |
| s03 权限系统 | ✅ 必选 | 高风险/付费/对外动作人工确认 |
| s05 任务规划 | ✅ 必选 | 阶段状态机、进度可查询 |
| s10 任务系统 | ✅ 必选 | 长任务持久化、断点续跑 |
| s16 工作流运行时 | ✅ 必选 | 阶段闸门是固定编排，脚本拥有编排 |
| s17 目标闭环 | ✅ 必选 | 闸门独立判断"何时算完成" |
| s09 记忆系统 | ✅ 需要 | 决策台账、项目状态跨会话持久化 |
| s11 后台任务 | ✅ 需要 | 长流程不阻塞 |
| s06 子 Agent | ⏸ 暂缓 | 先单 Agent 跑通 |
| s07 技能加载 | ⏸ 暂缓 | 手册数量有限，先内嵌 |
| s08 上下文压缩 | ⏸ 暂缓 | 先不处理长会话 |
| s12 定时调度 | ⏸ 暂缓 | 无定时自治需求 |
| s13 Agent 团队 | ⏸ 暂缓 | 无并行团队需求 |
| s14 MCP 插件 | ⏸ 暂缓 | 无外部工具生态需求 |
| s15 集成 Harness | ⏸ 暂缓 | MVP 先单循环，多机制协同后再集成 |

**选型原则遵守**：每个组件都回答了"没有它工厂会怎样"，答不上来的全部暂缓，不从完整而选。
