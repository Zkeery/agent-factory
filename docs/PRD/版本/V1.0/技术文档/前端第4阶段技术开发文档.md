# 第 4 阶段前端开发文档｜质量与发布准备

> 配套文档：《前端技术适配声明》、前端第 1-3 阶段技术开发文档、前端手册第 17-21 节。
> 本文档只覆盖前端子阶段 4（质量与发布准备）。这是前端阶段的收尾。

## 1. 本阶段目标

前端达到**可发布质量**：响应式、无障碍、性能达标，与真实后端联调通过，Console/Lint/类型/测试全干净，并产出发布说明与已知问题。

## 2. 范围

### 本阶段包含
- 响应式：桌面 1280/1024/768 + 移动 390/375 多宽度检查，无横向溢出
- 无障碍：表单项关联 Label、状态不只靠颜色、键盘可操作核心动作
- 性能：构建产物检查、无首屏不必要的大依赖
- 真实联调：真实模型（DeepSeek）走一遍完整闭环
- 清理：Console 无错误、Lint/类型/测试/构建全通过
- 发布说明：README 补发布说明 + 已知问题

### 本阶段不包含
- 登录/账号（后续阶段）
- Electron 桌面壳（后续）
- 完整视觉设计（产品经理未定视觉方向）

## 3. 用户流程
不变。本阶段是质量加固，不改功能流程。

## 4. 页面状态矩阵
沿用前端第 1-3 阶段，无变化。

## 5. 接口契约
无新增接口。沿用现有 runs/decisions/evidence/score/metrics/events。

## 6. 实现方案
- 响应式：Tailwind 断点 + 手动多宽度截图检查，修复溢出点。
- 无障碍：输入框/下拉补 `label` 或 `aria-label`；进度步骤保留文字（不只靠颜色）；关键按钮有可访问名称。
- 性能：检查 `next build` 产物与首屏依赖，确认无大库引入。
- 真实联调：后端切 deepseek，前端走一遍「提交→决策卡→PRD→确认→闸门通过→打分」。
- 发布说明：README 补「发布说明」与「已知问题」两节。

## 7. 验收标准
- Given 5 种宽度 / When 打开首页与走完流程 / Then 无横向溢出、布局正常。
- 无障碍：所有输入/下拉有关联 label/aria-label；状态有文字非仅颜色。
- 自动检查：`npm test` + `npm run e2e` + `npx tsc --noEmit` + `npm run lint` + `npm run build` 全通过。
- 真实联调：真实模型完整闭环走通一次（记录模型、耗时、成本）。
- Console：无错误输出。

## 8. 风险与回退
- 风险：视觉方向未定，无法做完整视觉打磨；降级：以「可用、可读、无溢出」为验收口径。
- 回退：本阶段多为检查与文案补全，回退移除改动即可。

## 9. 交付结果
- 修改文件：前端无障碍微调、README 发布说明
- 检查结果：单测/E2E/类型/Lint/构建 + 5 宽度截图 + 真实联调记录
- 未完成项：登录、Electron、视觉打磨（记录在案）
- 已知问题：待开发后回填
