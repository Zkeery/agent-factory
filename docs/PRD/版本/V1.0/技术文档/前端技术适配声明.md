# 前端技术适配声明

## 1. 项目判断
- 产品类型：Agent 产品工厂（操作台）——产品经理提交想法，看进度、回决策卡、确认 PRD、看证据、打分。
- 主要用户：非技术产品经理（MVP 先内部，终态对外）。
- 主要终端：**先 Web（桌面/移动浏览器），Electron 桌面外壳后置**（手册默认桌面端"在 Web 基础上评估"，Q2 的桌面应用是终态，不排斥先做 Web）。
- 新项目或已有项目：新项目（前端从零建；已有后端 FastAPI 提供 API）。
- 本阶段业务目标：把后端临时验收界面（单 HTML）升级为正式前端操作台的可运行骨架。

## 2. 输入资料
- PRD：已读取（V1.0）
- 后端手册：已读取（通用技术栈手册）
- 接口文档：完整（后端已实现 runs/decisions/evidence/score/metrics + SSE，契约见第 1-4 阶段技术开发文档）
- 设计稿：无（先做一版代表页给产品经理看）
- 现有代码：有（后端 + 临时验收界面，交互可参考）

## 3. 技术选择
- 框架与版本：Next.js（App Router）+ TypeScript strict + Tailwind CSS
- 样式与组件策略：CSS 变量定义语义化设计变量 + 轻量自建组件（先不引入完整组件库）
- 数据请求与状态策略：fetch + React 状态；任务状态统一由后端状态映射
- 流式通信策略：SSE（复用后端 `/runs/{id}/events`，事件 `chunk` × N → `done`/`error`）
- 表单方案：受控组件 + Pydantic 契约校验（后端已有）
- 测试方案：Vitest（组件）+ 类型检查 + Lint + 构建；核心闭环用 Playwright（后续子阶段）
- 部署环境：本地开发（`npm run dev`，端口 3010，同源代理后端 8010）

## 4. Agent 状态
- 后端状态 → 前端统一状态映射：

| 后端 current_stage | 前端展示 |
| --- | --- |
| idea_submitted | 提交想法 |
| clarifying / awaiting_answers | 澄清中 / 等待回答决策卡 |
| prd_drafting / awaiting_prd_confirm | 生成 PRD / 待确认 |
| building / testing / deploying | 构建中 / 测试中 / 部署中 |
| evidence_ready / gate_passed | 整理证据 / 闸门通过 |
| gate_failed / failed | 闸门失败 / 失败 |

- 等待用户确认方式：决策卡逐个回答、PRD 确认按钮。
- 取消、重试、断线恢复方式：SSE 断线重连 + 按 run_id 拉取状态回放（后端事件已持久化）。
- 任务 ID 和恢复入口：run_id 贯穿全程，刷新/重开按 run_id 恢复。

## 5. 页面与产物
- 核心页面（第一版骨架聚焦一页）：
  - **工厂工作台**：提交想法 → 进度条 → 决策卡 → PRD → 证据包 → 打分 → 度量汇总。
- 核心业务闭环：想法 → 闸门通过 → 打分 → 度量更新。
- 产物类型和预览方式：PRD（JSON 文本）、代码骨架（代码块）、部署脚本/验收清单（文本）。
- 响应式目标：桌面 1280px 与移动端 375px 都要可操作。

## 6. 偏离本手册的地方
- 偏离项：本阶段不引入 Playwright E2E（手册要求核心闭环 E2E）；改为后端已有 46 项 pytest + 前端 Vitest 覆盖，E2E 留到前端子阶段 2「第一条真实闭环」。
- 原因：第一版骨架重点是"能跑通"，核心闭环 E2E 等真实闭环阶段再加，避免过早投入。
- 影响：真实浏览器端到端覆盖延后一个子阶段，不影响本阶段验收（以接口联调 + 组件测试为准）。
