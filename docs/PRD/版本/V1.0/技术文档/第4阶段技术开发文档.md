# 第 4 阶段技术开发文档｜做实测试与上线部署脚本

> 配套文档：《Agent造物坊 PRD V1.0》、《技术适配声明》、第 1/2/3 阶段技术开发文档。
> 本文档只覆盖第 4 子阶段。不提前实现后续阶段能力。

## 一、阶段目标

- **交付范围**：把工厂流水线里两个"占位"工序做实——① 测试工序（当前只检查代码非空，改为真实语法检查 + smoke 测试）；② 新增部署工序（生成一键部署脚本 + 上线验收清单）。补齐蓝图 audit 的「可部署」短板。
- **阶段产物**：真实测试工序、部署脚本生成工序、部署产物（start.sh + 上线验收清单）、证据包。
- **验收标准**：工厂生产的每款产品能拿到「代码 + 一键部署脚本 + 上线验收清单」三样；测试工序对代码骨架跑真实 smoke 测试并记录结果；后端测试全绿。
- **明确不做**：真实云端部署（产品经理自部署自付，D3）；Docker/对象存储等生产级设施（后续阶段）；账号隔离（后续阶段）。

## 二、技术适配摘要

- 沿用第 1/2/3 阶段技术栈，不新增框架。
- 测试工序用 Python 标准库 `py_compile` 做语法检查 + `subprocess` 跑骨架 smoke 测试。
- 部署工序生成 `deploy/start.sh` + `deploy/上线验收清单.md`（本地单进程形态，符合 D3「工厂出脚本、产品经理自部署」）。

## 三、技术栈与模型

- 不变。模型 DeepSeek `deepseek-chat`；部署脚本由确定性代码生成（不交给模型）。

## 四、环境与配置

- 不新增配置项。

## 五、项目结构

```text
backend/app/services/
├── engine.py      # 新增 DEPLOYING 阶段动作
├── stages.py      # 新增 DEPLOYING 阶段
├── testing.py     # 测试工序：py_compile + smoke 测试（新增）
├── deploy.py      # 部署工序：生成 start.sh + 验收清单（新增）
└── gates.py       # 构建闸门改为「测试通过 + 部署脚本存在」
```

## 六、数据、资产与状态

- 状态机新增 `DEPLOYING` 阶段（在 TESTING 与 EVIDENCE_READY 之间）：

```text
... → BUILDING → TESTING → DEPLOYING → EVIDENCE_READY → GATE_PASSED
```

- 部署产物写入 `data/code/<run_id>/deploy/`（start.sh、上线验收清单.md），路径限制在 data/ 内。
- 测试结果作为 `test_result` 事件持久化（沿用现有机制）。

## 七、API / 工具设计

- API 不变（沿用 runs/decisions/evidence/score/metrics）。
- 证据包新增「部署产物」条目，产品经理可查看 start.sh 与验收清单内容。

## 八、Prompt 设计

- 本阶段无新 Prompt；部署脚本与验收清单由确定性代码生成，不调用模型。

## 九、验收界面或纵向切片

- 临时验收界面「证据包」区展示部署产物（start.sh、验收清单）。

## 十、测试要求

- 第一层 mock 测试：
  1. 测试工序：语法错误代码 → test_result=failed；正常骨架 → passed；smoke 测试真正执行。
  2. 部署工序：终态后 `deploy/start.sh` 与 `deploy/上线验收清单.md` 存在且非空。
  3. 闸门：测试失败 → 最终闸门不过；部署脚本缺失 → 闸门不过。
  4. 状态机：DEPLOYING 在 TESTING 之后、EVIDENCE_READY 之前。
  5. 回归：第 1/2/3 阶段测试保持通过。
- 第二层真实冒烟：本阶段无新模型契约，不重复真实调用。

## 十二、风险与待确认项

- 部署脚本是「本地单进程」模板，正式云端部署（veFaaS 等）在阶段 4 上线时再做。
- smoke 测试针对「固定流程 AI 应用」骨架，具体业务逻辑测试待真实产品生成后补。
- 必须由产品经理决定的问题：无。

## 十三、交接给下一阶段

- 就绪：工厂能产出「代码 + 部署脚本 + 验收清单」三样，六条验收标准（可运行/可容错/可观测/可测试/可部署/可度量）全部有落地。
- 下一阶段：阶段 2 后端 MVP 整体验收，或进入阶段 3 正式前端。
