# 第 1 阶段前端开发文档｜可运行骨架

> 配套文档：《前端技术适配声明》、后端第 1-4 阶段技术开发文档、PRD V1.0。
> 本文档只覆盖前端子阶段 1（可运行骨架）。不提前实现后续子阶段能力。

## 1. 本阶段目标

产品经理打开网页，能看到一个**正式的工厂工作台**：提交想法 → 看进度 → 回决策卡 → 确认 PRD → 看证据 → 打分 → 看度量。本阶段先把骨架和代表页搭起来，接通真实后端接口，桌面与移动端都能正常显示。

## 2. 范围

### 本阶段包含
- 页面：工厂工作台首页 `/`（单页，含完整流程区）
- 组件：顶栏布局、进度步骤条、决策卡列表、PRD 展示、证据列表、打分区、度量区、日志区
- 接口：runs/decisions/evidence/score/metrics/SSE（全部复用后端，不新增后端接口）
- 任务状态：后端 `current_stage` → 前端进度步骤映射
- 产物：PRD（JSON 文本）、代码骨架（代码块）、部署脚本/验收清单（文本）

### 本阶段不包含
- 登录/账号（后续阶段）
- Electron 桌面壳（后续）
- 多任务历史列表（后续子阶段）
- Playwright E2E（子阶段 2 再上）
- 完整视觉设计（先代表页，产品经理反馈后再细化）

## 3. 用户流程
1. 打开首页，在输入框填想法，点「提交，启动流水线」
2. 进度条逐步点亮（提交→澄清→…→部署→闸门通过）
3. 到「等待回答」时出现决策卡，逐张填答案提交
4. 到「待确认 PRD」时看到 PRD 全文，点「确认」
5. 看到证据包（PRD/部署产物/闸门检查）
6. 出现打分区，三维各选 1-3 分提交
7. 底部度量区数字更新

## 5. 接口契约

复用后端接口（详见后端第 1-4 阶段文档），前端通过 Next.js rewrites 把 `/api/v1/*` 代理到 `http://127.0.0.1:8010`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/runs` | 提交想法 |
| GET | `/api/v1/runs/{id}` | 拉取状态（含决策卡/证据） |
| POST | `/api/v1/runs/{id}/decisions/{code}/answer` | 回答决策卡 |
| POST | `/api/v1/runs/{id}/confirm-prd` | 确认 PRD |
| GET | `/api/v1/runs/{id}/events` | SSE 进度流（chunk→done/error） |
| POST | `/api/v1/runs/{id}/score` | 三维打分 |
| GET | `/api/v1/metrics` | 度量汇总 |

错误统一 `{"error":{"code","message"}}`；SSE 以 `done` 或 `error` 收尾；断线按 run_id 重新拉状态回放。

## 6. 实现方案
- 路由：App Router，`app/page.tsx` 为主页；`app/layout.tsx` 放顶栏。
- 组件结构：`components/ui/`（Button、Card、Select 等）+ `features/factory/`（提交区、进度条、决策卡、PRD、证据、打分、度量，按业务功能组织）。
- 状态来源：React `useState/useEffect` + 自定义 hook `useFactoryRun`（管理 run_id、stage、SSE 订阅）。
- 流式：`EventSource` 订阅 `/runs/{id}/events`，`chunk` 更新进度，`done` 拉终态，`error` 展示失败；断线重连 + 按 run_id 回放。
- 响应式：Tailwind 断点，桌面 1280 / 移动 375 都可用（单列自适应）。
- 安全与隐私：API Key 只在后端读取，前端不接触密钥；错误不泄露堆栈。

## 7. 验收标准
- Given 打开首页 / When 输入想法提交 / Then 进度条开始推进、SSE 收到事件。
- Given 到「等待回答」/ When 逐张回答决策卡 / Then 能继续到「待确认 PRD」。
- Given 到「待确认 PRD」/ When 点确认 / Then 最终「闸门通过」+ 证据包显示。
- Given 闸门通过 / When 三维打分提交 / Then 度量区数字更新。
- 目标浏览器/尺寸：Chrome 1280px 桌面 + 375px 移动，无横向溢出。
- 自动检查：`npm run lint`、`npx tsc --noEmit`、`npm run build`、`npm test` 全通过。
- 真实联调：前端连真实后端（mock 模式零成本）走通完整流程。

## 8. 风险与回退
- 风险：SSE 断线/浏览器兼容；降级：断线后按 run_id 轮询回放。
- 风险：视觉方向未定；降级：先出代表页，产品经理反馈后迭代，不铺开全部视觉。
- 回退：前端骨架独立于后端，回退 = 移除 `frontend/` 目录，后端不受影响。
