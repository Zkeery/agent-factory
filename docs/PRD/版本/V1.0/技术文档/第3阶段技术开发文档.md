# 第 3 阶段技术开发文档｜可度量落地

> 配套文档：《Agent造物坊 PRD V1.0》、《技术适配声明》、第 1/2 阶段技术开发文档。
> 本文档只覆盖第 3 子阶段（可度量落地）。不提前实现后续阶段能力。

## 一、阶段目标

- **交付范围**：把 D2 的验收标准（三维 1-3 分 + 合格线）落地成工厂可采集、可汇总的**度量体系**，对齐 PRD 的成功标准「稳定出货」。
- **阶段产物**：运行指标采集（耗时/token/成本）、质量打分接口、度量汇总接口、界面展示。
- **验收标准**：工厂能回答「稳定出货率、平均耗时、平均成本、质量合格率」四个数字；后端测试全绿；界面能看到度量。
- **明确不做**：自动判断质量（打分仍由产品经理人工）；对外多租户度量；图表可视化（后续）。

## 二、技术适配摘要

- 沿用第 1/2 阶段技术栈，不新增框架。
- 新增 `RunMetric` 表（新表，create_all 自动建，不改旧表）。
- LLM 客户端增加 token 累计；engine 结束时落 metric。

## 三、技术栈与模型

不变。模型仍 DeepSeek `deepseek-chat`；mock 阶段 token 计 0。

## 四、环境与配置

新增配置（`.env.example` 同步）：
- `COST_PER_1M_INPUT=1.0`、`COST_PER_1M_OUTPUT=2.0`（DeepSeek deepseek-chat 约价，用于成本估算，非账单）

## 五、项目结构

```text
backend/app/
├── models/__init__.py      # 新增 RunMetric 表
├── schemas/__init__.py     # 新增 ScoreRequest / MetricsOut
├── services/metrics.py     # 采集 + 汇总
└── api/runs.py             # 新增 /score、/metrics 接口
```

## 六、数据、资产与状态

新增 `run_metrics` 表（schema v2，只加表不改旧表）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| run_id | str FK | 关联运行 |
| duration_seconds | float | 提交到终态的耗时 |
| prompt_tokens | int | 累计输入 token |
| completion_tokens | int | 累计输出 token |
| cost_estimate | float | 估算成本（元） |
| score_decision / score_prd / score_code | int nullable | 产品经理三维打分（1-3） |
| created_at | datetime | 记录时间 |

## 七、API / 工具设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/runs/{id}/score` | 产品经理打三维分 `{decision, prd, code}` 各 1-3 |
| GET | `/api/v1/metrics` | 汇总：总运行数、稳定出货率、平均耗时、平均成本、质量合格率 |

- 打分仅对终态（gate_passed/gate_failed/failed）的 run 开放；重复打分覆盖。
- 度量汇总由确定性代码计算，不交给模型。

## 八、Prompt 设计

本阶段无新 Prompt。

## 九、验收界面或纵向切片

临时验收界面新增「度量」区，展示四个数字；完成的生产可打三维分。

## 十、测试要求

- 第一层 mock 测试：
  1. metric 在 run 到终态时落库（耗时/token 正确）。
  2. 打分接口：终态可打、非终态 409、重复打覆盖、分数越界 422。
  3. 度量汇总：稳定出货率、平均耗时、平均成本、合格率计算正确（构造固定数据断言）。
  4. 回归：第 1/2 阶段测试保持通过。
- 第二层真实冒烟：本阶段无新模型契约，不重复真实调用。

## 十一、验收清单（产品经理照着做）

- [ ] 打开 http://127.0.0.1:8010/，看到「度量」区有四个数字
- [ ] 提交一个想法走完流程后，度量区数字变化（运行数 +1）
- [ ] 对一个完成的运行打三维分（1-3），能看到记录

## 十二、风险与待确认项

- 成本估算非账单，仅用于度量（DeepSeek 实际价格以官网为准）。
- 质量分是人工判断，合格率只统计「已打分」的运行。
- 必须由产品经理决定的问题：无。

## 十三、交接给下一阶段

- 就绪：度量采集、打分、汇总；下一子阶段（做实测试/上线部署脚本）可复用「稳定出货率」作为验收指标。
