# 第 2 阶段技术开发文档｜接真实模型

> 配套文档：《Agent造物坊 PRD V0.1》、《技术适配声明》、第 1 阶段技术开发文档、通用技术栈手册。
> 本文档只覆盖第 2 阶段（后端 MVP 第二个子阶段）。不提前实现后续阶段能力。

## 一、阶段目标

- **交付范围**：把第 1 阶段的 mock 生成，换成**真实模型调用**，覆盖三个环节——澄清决策卡、PRD 草稿、代码骨架。工厂的流水线（状态机/闸门/持久化/界面）保持不变。
- **阶段产物**：真实 LLM 调用层（OpenAI 兼容接口 + 超时 + 有限重试 + 结构校验）、Prompt 文件、配置项、真实冒烟记录。
- **验收标准**：用真实 Key 跑通「想法 → 决策卡 → PRD → 代码骨架」整条链路，模型输出通过结构校验，SSE 正常收尾；mock 测试仍全绿。
- **明确不做**：真实"上线部署"工序（后续子阶段）、多模型对比、自动选模型、前端正式化。

## 二、技术适配摘要

- 本阶段采用：延续第 1 阶段技术栈（FastAPI + SQLAlchemy + pytest + 临时界面）。
- 本阶段启用：真实模型客户端（openai 库，OpenAI 兼容协议指向 DeepSeek）。
- 本阶段偏离/暂缓：真实 Key 未到前，`LLM_PROVIDER=mock` 仍走 mock；Key 到后切 `deepseek` 做真实冒烟。
- 开发路径：后端先行。

## 三、技术栈与模型

| 组件 | 选型 |
| --- | --- |
| 模型厂商 | DeepSeek（国内、低成本、OpenAI 兼容） |
| 模型名 | `deepseek-chat` |
| 客户端 | openai 库，`base_url=https://api.deepseek.com` |
| 校验 | Pydantic（决策卡 / PRD 结构化输出） |

## 四、环境与配置

- `.env` 新增（`backend/.env.example` 同步更新，不含真实值）：
  - `LLM_PROVIDER=mock`（开发）或 `deepseek`（真实）
  - `LLM_API_KEY=`（DeepSeek Key，验收前填）
  - `LLM_BASE_URL=https://api.deepseek.com`
  - `LLM_MODEL=deepseek-chat`
- 需要用户提供：DeepSeek API Key（验收前填 `.env`）。
- 无 Key 不阻塞开发：`LLM_PROVIDER=mock` 继续跑通全流程。

## 五、项目结构

```text
backend/app/services/
├── llm.py          # LLM 接口 + 工厂（get_llm）+ RealLLM（OpenAI 兼容）
├── mock_llm.py     # MockLLM（保留，离线占位）
├── parsing.py      # 模型输出的确定性解析 + Pydantic 结构校验
└── prompts/
    ├── clarify.md  # 决策卡生成 Prompt
    └── prd.md      # PRD 生成 Prompt
```

## 六、数据、资产与状态

- 本阶段不新增表；沿用第 1 阶段表结构。
- 模型调用记录：日志记录模型名、耗时、token 用量、错误类型（不含密钥与敏感原文）。

## 七、API / 工具设计

- API 接口不变（沿用第 1 阶段 runs/decisions/evidence）。
- 引擎工具不变；仅将 `mock_llm` 的生成函数替换为经 `get_llm()` 分发的实现。
- SSE 约定不变：`chunk` × N → `done` 或 `error`。

## 八、Prompt 设计

- `prompts/clarify.md`：输入想法，输出 ≤5 个"必须问"决策卡 JSON（字段：code/question/options/recommendation/consequence）。正反例约束：必须是 JSON 数组、禁止超 5 个、禁止 `#`/`1.1` 等非 JSON 格式。
- `prompts/prd.md`：输入想法 + 决策卡结论，输出 8 字段 PRD JSON。
- 解析规则（parsing.py）：
  - 模型输出先剥掉 ```json 围栏，再 JSON 解析；
  - Pydantic 强校验；校验失败有限重试（≤2 次）；
  - 数量/内容约束不遵守（如决策卡 >5 但结构正确）记为瑕疵，交产品经理判断，不反复重试烧钱。

## 九、验收界面或纵向切片

- 沿用第 1 阶段临时验收界面，无改动。

## 十、测试要求

- 第一层 mock 测试（pytest）：
  1. `get_llm()` 在 `mock` 配置下返回 MockLLM、`deepseek` 配置下返回 RealLLM。
  2. 解析器：合法 JSON 通过、带 ```json 围栏通过、非法 JSON 重试后仍失败走统一错误。
  3. 决策卡数量 >5 时记为瑕疵而非解析失败。
  4. 无 Key 时 RealLLM 初始化抛 AppError（不泄露 Key）。
  5. 回归：第 1 阶段 13 项测试保持通过。
- 第二层真实冒烟（待 Key）：用真实 DeepSeek Key 跑通一条「想法 → 决策卡 → PRD → 代码骨架」完整链路，记录模型、耗时、token、成本、结构合规率。

## 十一、验收清单（产品经理照着做）

- [ ] 填好 `.env` 的 `LLM_API_KEY`（按 AI 给的照着点步骤申请 DeepSeek Key）
- [ ] 打开 http://127.0.0.1:8010/，提交一个想法
- [ ] 看到决策卡是"针对你想法"的问题（不再是千篇一律的模板）
- [ ] 回答决策卡后，PRD 草稿是针对你想法写的内容
- [ ] 确认 PRD 后，代码骨架是针对你想法生成的内容
- [ ] 全程以「闸门通过」收尾

## 十二、风险与待确认项

- 成本：DeepSeek 按 token 计费，单次生成约几分钱量级；真实冒烟前先核价。
- 模型输出质量：结构校验能保证格式，不能保证内容质量；内容质量待真实样例打分（D2 待样例打分）。
- 必须由产品经理决定的问题：无（模型厂商已定 DeepSeek）。
