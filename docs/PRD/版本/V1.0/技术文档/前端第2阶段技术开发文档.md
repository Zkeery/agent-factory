# 第 2 阶段前端开发文档｜第一条真实闭环 + 失败展示 + E2E

> 配套文档：《前端技术适配声明》、前端第 1 阶段技术开发文档、后端第 1-4 阶段文档。
> 本文档只覆盖前端子阶段 2。不提前实现子阶段 3（多任务历史、取消重试）能力。

## 1. 本阶段目标

产品经理不仅能跑通正常流程，还能在**失败时看清原因**；并且核心闭环有了**浏览器 E2E 测试**兜底，保证每次改动不把主链路弄坏。

## 2. 范围

### 本阶段包含
- 失败展示：gate_failed / failed 时前端明确标红并展示错误原因
- 失败态进度条：failed 步骤标红
- 核心 E2E：Playwright 跑「提交想法 → 决策卡 → 回答 → PRD → 确认 → 闸门通过」闭环
- 后端小改：失败时 SSE 的 error 事件前端能正确读取（如需要）

### 本阶段不包含
- 多任务历史列表 / 任务中心（子阶段 3）
- 取消、重试、断线恢复按钮（子阶段 3）
- 登录、Electron、完整视觉（后续）

## 3. 用户流程
1. 正常流程（沿用第 1 阶段）
2. 当流水线失败（如模型 Key 缺失、代码语法错误），进度条标红，页面显示红色错误原因
3. 用户能看到「失败原因」，据此决定重试或反馈

## 4. 页面状态矩阵

| 模块 | 运行 | 成功 | 失败 |
|---|---|---|---|
| 进度条 | 当前步高亮 | 全亮 | failed 步标红 |
| 错误提示 | 无 | 无 | 红色卡片显示 error.message |
| 打分区 | 无 | 显示 | 无 |

## 5. 接口契约

- 后端失败时：SSE 发 `event: error`，data 为 `{"error":{"code","message"}}`；run 的 current_stage 为 `failed`（或 `gate_failed`）。
- 前端：收到 error 事件时记录 message；收到 failed/gate_failed chunk 时展示错误卡片。

## 6. 实现方案
- 前端 hook 增加 `failure` 状态（SSE error 事件写入 message）。
- 进度条：failed 步骤标红。
- 错误卡片：isTerminal 且 stage 为 failed/gate_failed 时，展示红色错误原因。
- E2E：新增 `frontend/e2e/factory.spec.ts`，Playwright 起真实前端（3010）+ 后端（8010，mock），断言完整闭环。

## 7. 验收标准
- Given 正常提交 / When 走完流程 / Then 闸门通过 + 打分 + 度量更新（E2E 覆盖）。
- Given 后端失败（模拟模型 Key 缺失）/ When 提交 / Then 页面标红并显示错误原因。
- 自动检查：`npm test`（含 E2E）+ `npx tsc --noEmit` + `npm run lint` + `npm run build` 全通过。
- 目标浏览器/尺寸：Chrome 1280 桌面 + 375 移动。

## 8. 风险与回退
- 风险：Playwright 浏览器安装/环境问题；降级：E2E 用等价的可重复验收步骤（curl 脚本）替代，如实标注。
- 回退：失败展示仅前端改动，回退移除对应组件即可。

## 9. 交付结果
- 修改文件：前端失败展示组件、e2e 测试、可能的后端 SSE 微调
- 检查结果：E2E + 单测 + 类型/Lint/构建全通过
- 未完成项：多任务历史、取消重试（子阶段 3）
- 已知问题：待开发后回填
