# 项目列表与版本导航

日期：2026-10-05。版本仍为 V1.2。

## 用户行为

左侧「我的项目」按项目 ID 展示，每个项目只占一行、保留一个删除入口，行内显示版本数与最新进度。点击项目默认打开最新生成的版本；同名但不同 ID 的项目保持独立。尚未构建的项目保留在列表中。

项目内部顶部提供「项目版本」选择器，显示 V1/V2、初版或修改版、最新标记、时间与阶段。编号按生成时间排序，仅作为展示标识。切换版本同步恢复对应需求、场景和运行状态；选择旧版仍高亮同一项目，刷新保留当前版本。搜索可以匹配项目名称、概要和历史版本的想法，命中后保留完整项目及其全部版本。

顶部回收站入口始终显示「回收站」文字，进入后显示「返回项目」；项目恢复按钮也显示「恢复」。删除确认继续明确「整个项目及全部 N 个版本移入回收站，可以恢复」。既有软删除、定时任务暂停和后端归属校验不变。

## 实现

`frontend/lib/projectNavigation.ts` 负责项目分组、稳定排序和搜索。`ProjectNavigation` 组件负责项目导航与回收站；`ProjectVersionPicker` 在中栏独立一行呈现当前项目的全部版本，复用原 `handleSelect` 与恢复 API。

分组依赖项目 ID，不以同名字符串合并。项目元数据与版本列表分别加载时，按项目 ID 暂时归组；没有项目归属的历史记录独立保留且不显示整项目删除按钮。新增版本尚未出现在列表中时保留当前版本占位，防止错误选择其他版本。不新增后端接口、数据库迁移或模型调用。

手机视口下选择器收缩到可用宽度，项目仍通过抽屉访问。任务标题设置合理的基础宽度，空间不足时操作按钮换到下一行，避免标题被挤成窄列。

## 验证

前端 53/53 测试通过，包含 5 个项目归属、同名隔离、历史版本搜索、空项目和排序回归；新增组件与 helper 的 ESLint 通过；最终 Next.js 生产构建与 TypeScript 通过。桌面 1440×900、手机 390×844 已验证两版本项目单行展示、旧版切换与刷新、删除取消、整项目移入回收站、刷新后恢复全部版本。只使用明确标识的 Mock 导航夹具，未调用模型或确认业务交付。

## 2026-10-10 失败版本重跑后的列表

用户看到的版本序号不读取库里的创建计数。同一项目里没有被替代的版本，按创建时间、再按标识从 V1 连续编号。被整段重跑替代的失败版本不占号，因此不会留下 V2、V4 这种间隔。例如原先 V1 至 V7 中 V1、V3、V5 已被重跑替代时，剩下的四条按创建顺序显示为 V1 至 V4。新的重跑版本排在当时可见版本的末尾，序号继续相连。

用户对失败或闸门失败的版本执行整段重跑，并且新版本已经创建后，旧版本记下 `superseded_by_run_id`。这是用户不可见的标记，不是物理删除，也不进入回收站：物理删除会断开父子关联、复盘统计和产物文件引用。项目版本选择器、版本数量、「N 个版本」和侧栏只统计没有这条替代关系的运行。修改版对外展示的父版本若指向已被替代的失败版本，则改指替代链上仍可见的版本；库里的父子关联保持原样。直接打开已被替代的地址时，进入新版本。复盘指标仍计入该次失败，版本记录表不再列出它。

已交付、待验收、等待回答等非失败阶段继续展示。用户没有重跑的失败版本继续展示。已取消后的重跑、就地重测、基于成品的修改版和定时创建都不隐藏原版本。升级已有数据时，按同一次制作谱系把已经重跑过的失败版本补上替代关系，只做一次。展示序号在读取时按上述规则计算，不改写已经保存的创建计数。
