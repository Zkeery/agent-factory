## 2. 一次运行如何经过这些模块

用户在 React 工作台提交想法，FastAPI 创建运行并保存到 SQLite。需求澄清与 PRD 确认后，由标准工作流或 Agent 协作模式执行生成和检查，代码与证据写入本项目文件目录。前端通过 SSE 接收当前运行的进度，通过列表轮询发现其他运行。自动检查通过后等待用户试用和人工验收；用户明确通过后才按现有规则交付。

协作模式中，开发 Agent 可读写受控应用文件并执行检查；验证 Agent 读取文件、运行检查、反馈问题或给出结论。确定性代码限制工具权限、路径、每角色每轮最多 6 次模型调用及最多 2 轮修复，并保存恢复所需状态。模型判断和自动检查均不等同人工业务验收。

## 3. 当前运行方式

- 本地前端端口为 3010，后端为 8010，配置见 [project.json](../../../../../project.json)。当前业务数据库为 SQLite，尚无公网生产部署。
- 模型配置和业务配置保留在本项目环境配置中，文档只记录提供方、模型名和能力边界，不保存凭证。
- 代码包含 Docker 沙箱实现，当前 `sandbox_mode=auto`；可用时选择容器路径，否则回退到本机进程。不能据此声称当前全部检查和预览都已在 Docker 中隔离。见 [进程检查](../../../../../backend/app/services/sandbox.py)及 [Docker 实现](../../../../../backend/app/services/docker_sandbox.py)。
- Electron 桌面壳承载同一套本地服务。网页部署、完整安装包分发、云端持续调度和多租户生产隔离不计为当前已经完成的交付。

## 4. 自动更新的执行规则与已知差距

后端每 30 秒扫描一次定时任务，匹配本地 `HH:MM`；页面可见时每 5 秒同步运行、项目及定时列表，统计独立每 30 秒更新。同步请求 12 秒超时后取消并允许后续重试，晚到的过期响应不得覆盖新状态。正常情况下的扫描与同步间隔不是端到端时延保证，还受网络、服务和浏览器调度影响。

1. 当前侧栏定时入口创建的 Schedule 未绑定项目时，调度只创建 `project_id` 为空的 Run。前端兼容展示，但完整项目删除与版本归并尚未覆盖，后续应统一项目身份。
2. 定时 API 的时间字段目前校验 `HH:MM` 格式；界面通过选择器约束小时和分钟范围。直接 API 请求的取值范围校验仍需补强。
3. 后端关闭期间错过的定时任务不补跑；不支持用户单独选择时区。
4. 用户反馈过一次新定时运行未及时显示，其具体原因尚未确认。现有修复覆盖请求挂起、超时恢复与可见同步状态，受控浏览器验证不能代替长期环境验证。

以上差距作为后续开发输入，不能在 PRD 或项目介绍中写为已完成。同步验证详情见 [验收记录](../验收证据/定时选择与自动更新/验证记录.md)。
