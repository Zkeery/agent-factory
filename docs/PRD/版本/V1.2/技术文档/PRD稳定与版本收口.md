# PRD 稳定与版本收口

日期：2026-10-11。版本仍为 V1.2。产品契约见 [V1.2 PRD](../PRD.md)。

## 需求生成

`prd_quality.py` 仍拒绝空对象、全待定、缺必需章节、缺功能编号、验收未覆盖功能，以及不足三条用例。验收四类改为含义判定：主路径、空输入或超限、限制或禁止或隐私、可观察结果，同义表述算覆盖，不要求逐字出现「正常」「边界」「约束」「预期」。

结构已经成立、只缺其中一小项时，`validate_generated_prd` 在质量边界前按已写用例补一句归类说明，不整份失败，也不新增功能。`generate_prd` 最多 3 次尝试、输出预算 8000 token 不变。下一次提示带上具体缺口，或 JSON 无法解析的位置摘要。三次仍失败时，用户看到缺了哪一节或无法解析的原因。日志记录同一摘要，凭证样式先替换再写入。历史已保存的需求文档不自动改写。

## 嵌入脚本换行

开发提示要求整页 HTML/JS 放在原始字符串里。`repair_embedded_js_newlines` 在协作写文件和标准工作流落盘前执行：普通三引号里的页面脚本若出现未转义真换行，写成运行后仍是转义换行的源码。已经安全的源码原样返回。行注释和块注释里的撇号不当作字符串。引号未闭合、块注释或模板字符串未结束时不改源码，成品护栏仍会拦截字符串里的真换行。路径、角色权限、每角色每轮 8 次调用和最多 3 轮修复不变。

## 验收未通过的父版本

运行阶段保持待人工验收，验收记录仍可打开，用户仍可改判走通后交付。已经创建修改版、且主流程未通过时，版本选择器、侧栏、工作台和复盘显示「验收未通过 · 已由第 N 版替代」。N 是最新可见修改版的展示序号，按现有父子关系和可见版本顺序在读取时计算，历史数据同样适用。该父版本在复盘中记为已替代，不再计入待完成，也不进入交付率分母。没有未通过记录的父版本仍显示「待验收 · 已生成修改版」。

## 复盘口径

`/metrics` 与 `/metrics/review` 只统计版本列表里仍可见的运行。整段重跑后已隐藏的失败版本不进入总数、失败数、交付率和其他复盘分母。记录、真实父子关联和产物文件仍保留。

## 定时规则返回

`POST /api/v1/schedules` 与 `PATCH /api/v1/schedules/{id}` 使用和列表相同的等待运行查询。该规则已有未结束、等待用户的运行时，返回 `pending_run_id` 和 `pending_run_stage`；没有时这两项为空。
