# 主路径检查与进程回收

产品契约见 [V1.2 PRD](../PRD.md)。检查入口在 `backend/app/services/runner.py`，协作停止规则在 `backend/app/services/agent_harness.py`。

## 主路径请求体

自动检查的主路径是 `POST /generate`，`Content-Type` 为 `application/json`，请求体只有一个 `input` 字段，必须返回 HTTP 2xx 和 JSON。视频类仍要求响应里有非空 `video_url`。

请求正文按这个顺序取，取到就停，并去掉多余空白，最长 240 字：

1. 验收场景里主流程那一条的 `input`。优先 `id` 为 `main-flow` 的条目，其次标题含「主流程」「主链路」或「主路径」的条目，否则用第一条。
2. 需求说明里 `main_loop`、`input_process_output`、`goal_users` 中第一条有内容的行。
3. 本次想法的第一条有内容的行。
4. 都没有时使用约定默认输入：`按主路径完成一次默认处理`。

不再发送固定的 `{"input":"ping"}`。开发任务里的 `build_contract.smoke_request` 是这一次实际会发的请求体，`smoke_contract` 说明该请求必须成功。开发提示、验证提示和代码生成提示写了同一条契约：业务若必须先选择功能，请求没带该字段时按主路径默认选项继续，并在结果里写明所用默认，不要再用 4xx 要求检查补传请求体里没有的字段。

返回 404 时仍记为「主路径 /generate 不存在」。其他 4xx 且能读出 `detail`、`message`、`error` 或校验说明时，失败文本包含三件事：检查发了 `POST /generate` 和哪份请求体、应用返回了什么、改法是让这份请求体直接走完主路径并返回成功 JSON。公开检查摘要只保留诊断的最后一行，避免把源码行写进用户可见记录；完整诊断留在工具会话里。

## 同一原因提前停止

失败签名把空白压成一格、忽略大小写，并把 `127.0.0.1` 后面的端口换成同一占位，避免换端口被当成新原因。检查通过会清掉连续计数。

连续第 2 次同一签名时，工具结果附上提示：下一次仍是同一原因就会停止。连续第 3 次时执行失败，公开原因写明最近一次检查和下一步，不再进入剩余的修复轮。原因不同的连续失败仍用满最多 3 轮修复。开发自跑和验证对同一份源码各算一次观察。工作台对这条停止原因显示「同一个检查错误重复出现，自动修复已停止」。

## 端口归属与进程回收

旧检查在 8100–8190 里绑定一个端口，确认能绑上后立刻释放，再让子进程自己重新绑定。就绪只看 `openapi.json` 能否打开，不核对监听者是不是刚启动的进程。并行检查可以同时看中同一端口：先释放的一方若没抢回绑定、进程又还没退出，它发出的请求会打到后占用该端口的另一个应用上。这能解释开发第 0 轮自跑通过、验证紧接着对同一份源码失败的现象。本次改动没有回放 2026-10-11 那条算命运行的进程记录，所以上述是代码路径上成立的竞态，不是那一次运行的抓包结论。

已经有进程占着某个端口时，旧的绑定探测会跳过它。因此自 2026-10-05 起占着 8104、工作目录落在某个运行代码目录里的遗留进程，本身不会被选成下一次检查的端口，也不能单独解释「假通过」。它说明另一件事：检查和预览子进程此前可能在父进程结束后继续活着。旧检查不落进程记录，停止只向直接子进程发信号，后端进程退出也不会带走子进程。

现在的检查和预览先在 `127.0.0.1` 上由系统分配端口并开始监听，把这个已经在听的套接字交给 `uvicorn --fd`，父进程关掉自己的副本。子进程独立会话，进程号等于进程组号。Linux 能读 `/proc` 时，用 `/proc/net/tcp` 的监听 inode 对照该进程及其子进程的套接字；确认不是本次进程才作废结果。macOS 没有 `/proc`。这时用 psutil 看进程是否存在、状态、工作目录和监听连接；连接读不到时再查 `lsof -a -p <pid> -iTCP:<port> -sTCP:LISTEN`。进程组是否还有存活成员，用 `os.killpg` 和 `ps` 的进程组号，不把已经退出的组长当成仍在服务。归属实在判断不了、但这次启动的子进程仍在运行时，不作废结果：监听套接字是用 `--fd` 交给它的。确认是别的进程在听，仍然作废。并行检查各自持有自己的套接字，不会共用对方的端口。

检查开始前写入 `data/preview/probe-<pid>.json`，结束时删除记录并按进程组停止。组长已经退出、只剩尚未回收的记录时，不再把它当成仍在运行，避免每次检查空等数秒。进程退出时也会停掉仍在跟踪的子进程。下一次检查或预览启动时，回收记录仍在、且工作目录位于本项目代码目录下的遗留检查进程；仍由本次进程跟踪的检查不动。没有记录文件的旧遗留进程不会被盲目杀掉。预览状态在有进程组号时一并写入；旧状态文件没有该字段时仍可按进程号停止。查看预览状态不会杀掉仍在监听的健康进程。停止预览时，只有工作目录在代码目录下，或该进程仍拥有记录中的端口，才按进程组停止。

## 注释里的撇号

写 `app.py` 时，普通三引号里的页面脚本若含未转义真换行，仍会改成转义形式。扫描时跳过 `//` 行注释、`/* */` 块注释和反引号模板，注释里的英文撇号（例如 `// don't`）不再被当成字符串边界。引号未闭合、块注释或模板未结束时视为不确定，源码原样保留，成品护栏继续拒绝字符串里的真换行。已经安全的源码不改。
