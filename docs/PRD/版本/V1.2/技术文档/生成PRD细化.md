# 生成 PRD 细化

日期：2026-10-05。版本仍为 V1.2。范围为工厂生成给用户的单个产品 PRD；项目自身契约见 [V1.2 PRD](../PRD.md)，进度见 [项目状态](../../../../项目状态.md)。

## 内容与协议

维持现有 9 键 JSON 协议：8 个正文值仍是字符串，`output_type` 沿用原协议。正文内部使用 Markdown 子章节，不把页面或功能改成新的顶层对象。

| 正文字段 | 必需子章节 |
| --- | --- |
| `goal_users` | 用户与场景、问题与目标、依据与假设 |
| `input_process_output` | 输入与校验、处理步骤、结果与保存 |
| `main_loop` | 页面与字段、功能规格、状态与异常 |
| `quality` | 业务验收、质量边界 |
| `delivery` | 本期范围、暂不做、后续迭代 |
| `model_cost` | 模型使用、费用与限制、失败处理 |
| `data_nonfunc` | 数据对象、保存与恢复、数据边界 |
| `launch` | 运行与交付、账号与配置、待确认问题 |

页面字段写明作用、默认/必填及校验；功能使用 F01 等稳定编号，并写清触发、行为与结果；状态说明用户能做和不能做的操作。验收至少 3 条 AC01 等编号场景，覆盖正常、边界与约束，列出操作和可观察的通过条件，引用已定义功能编号。未确认细节可以注明缺口及影响，不能用空对象、全待定或只有标题的正文替代需求。

参考 [AI造梦机 PRD V1.3](../../../../../../AI造梦机/docs/PRD/PRD.md) 的页面字段、状态动作和可执行验收写法，依据来自该文 §1、§2.6、§9、§11。只迁移结构与细节表达，不照搬视频/漫剧、供应商、预算、并发或参数数值；也不把参考项目的历史验证结果写成新产品成绩。

## 生成与兼容

- 每项决策输入保留完整 `options`、`recommendation` 及解析后的回答。“按推荐”和 A/B 选择解析为具体答案，Q2/Q3 已确认的范围和约束保留在生成依据中。
- RealLLM 的 PRD 输出预算为 8000 token，首次生成与修复合计最多 3 次尝试。将结构缺口作为反馈要求修复，重试仍受原预算和失败处理约束。
- 新生成结果执行严格完整性检查，拒绝空对象、全待定、缺必需章节及功能/验收结构缺口。该门禁检查结构，不能判断所有语义是否正确，也不等于产品业务质量通过。
- 严格生成检查与历史解析分开：历史 PRD 继续按已有兼容方式读取，已有内容不自动改写。用户补充或纠错后，下一次重生成使用新标准。
- 前端在右侧成果区按 GFM 渲染表格，宽表使用独立横向滚动容器，不扩大整个工作区。
- Mock 的字段表和验收用例使用同一业务范围，普通补充规则保留原业务字段；Mock 仍是离线示例，不能证明真实模型语义理解。
