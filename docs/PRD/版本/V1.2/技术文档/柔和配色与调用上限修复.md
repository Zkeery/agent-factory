## 失败原因和恢复契约

开发 Agent 第六次模型调用执行了 `run_checks`，当前源码实际检查已通过；旧执行器仍要求再调用一次模型来提交 `handoff`，下一轮因达到六次调用上限返回失败。此前两次检查因生成代码尝试导入受限联网模块失败，已由模型修复。

修复保留每角色每轮六次调用上限。仅在开发角色用满预算、最新实际检查通过且属于当前角色/轮次、源码哈希一致、三个文件完整、无待提交或未完成动作时，执行器记录 `budget_handoff` 并交给验证 Agent；不生成或伪造模型结论。验证角色继续独立检查，最终业务验收仍由用户完成。

旧失败任务只在失败代码、原因和执行记录精确匹配这类预算误判，且满足上述证据条件时，允许通过“继续验证”恢复同一 Run。恢复保留 PRD、决策、源码、调用计数、修复轮数与执行历史，从构建阶段进入验证，不能直接跳到人工验收。普通失败、检查未通过、源码变化或其他不完整状态不享有这个恢复入口。

“整段重跑”创建新 Run 时复制原执行模式，修复之前静默退回标准工作流的问题。产品视角增加协作失败与调用上限的明确提示。
