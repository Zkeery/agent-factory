# 第十二刀热修｜沙箱常见依赖（pillow 等）

> 配套：试衣 Run `f6f9d625-7d74-4f4b-9114-1a8044e1cdb1` 闸门失败复现。  
> 性质：热修，不新开刀编号大功能。

## 一、问题

试衣项目闸门失败，UI 显示类似 `from PIL import Image, ImageDr`（截断假象）。完整 stderr 实际是：

```text
ModuleNotFoundError: No module named 'PIL'
```

Docker 不可用时走进程沙箱（backend `.venv`），该环境原先未装 pillow；Docker 镜像 Dockerfile 也只预装了 fastapi / pydantic / uvicorn。

## 二、根因

1. **依赖缺口**：生成代码的 `requirements.txt` 声明了 `pillow` / `python-multipart`，但沙箱运行环境（进程 venv / 冒烟镜像）未预装，`import app` 即失败。
2. **错误展示误导**：失败信息用 `err[:300]` 取 stderr **开头**，长 traceback 被截在 `from PIL import Image, ImageDr`，掩盖真正的 `ModuleNotFoundError`。

## 三、改动

| 路径 | 改动 |
| --- | --- |
| `backend/sandbox/requirements-smoke.txt` | 新增：fastapi / uvicorn / pydantic / pillow / python-multipart / openai |
| `backend/sandbox/Dockerfile` | 改为 `pip install -r requirements-smoke.txt` |
| `backend/requirements.txt` | 增加 `pillow`、`python-multipart`（进程沙箱走 backend venv） |
| `backend/app/services/sandbox.py` | 新增 `format_sandbox_import_error`：优先末尾 `ModuleNotFoundError`/`ImportError`，否则取 stderr **末尾** ≤300 字 |
| `backend/app/services/docker_sandbox.py` | 复用同一格式化函数 |
| `backend/tests/test_sandbox.py` | 覆盖 PIL smoke + 长 traceback 格式化断言 |

## 四、复验步骤

1. 确认 backend `.venv` 已安装 pillow（本机热修时已 `pip install pillow python-multipart`；新环境可 `pip install -r requirements.txt`）。
2. 打开失败的试衣 Run（或任意依赖 PIL 的 Run），在工作台点「重试」闸门 / 重新跑测试。
3. 预期：沙箱导入通过；若仍失败，UI/日志应能看到完整 `ModuleNotFoundError: No module named '…'`，而不再停在 `ImageDr` 截断。
4. （可选）有 Docker 时重建镜像：`docker build -t agent-factory-sandbox:local -f sandbox/Dockerfile sandbox`。
