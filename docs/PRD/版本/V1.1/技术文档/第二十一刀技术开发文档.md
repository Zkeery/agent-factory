## 一、阶段目标

让桌面壳（Electron）更像一个「正经应用」：**记住窗口位置和大小**，并提供**打包成 .app 的配置**（打包/签名仍后置）。

### 本刀产物

| # | 路径 / 行为 |
| --- | --- |
| 1 | 窗口状态记忆：位置/大小持久化到 `userData/window-state.json`，启动恢复；非法值回退默认 |
| 2 | 窗口标题、基础安全（`contextIsolation` 已有）不变 |
| 3 | electron-builder 配置 + `npm run dist` 脚本（打包 .app 骨架；后端仍依赖本机 Python/venv，公网分发后置） |
| 4 | README 说明桌面端打包方式；commit 停 |

### 明确不做

- 不做真·自包含安装包（捆绑 Python/后端/前端 build，工作量大且属上线范围）
- 不做 macOS 签名/公证、Windows 打包
- 不改后端/前端功能

## 二、现状与缺口

| 问题 | 现状 | 缺口 |
| --- | --- | --- |
| 每次启动窗口回到默认 1280×820 | `createWindow` 固定尺寸 | 无状态持久化 |
| 无打包配置 | `electron electron/main.cjs` 开发模式 | 无 electron-builder 配置 |

## 三、方案

### 3.1 窗口状态记忆（electron/main.cjs）

- 状态文件：`path.join(app.getPath("userData"), "window-state.json")`，内容 `{ width, height, x, y }`
- `createWindow()` 时读文件；有合法值则用（`width>=minWidth`、`height>=minHeight`，x/y 不越界屏幕则用）
- 监听 `resize`/`move`（去抖）写回；`close` 时也写一次

### 3.2 打包配置

- `package.json` 增加 `"build"`（appId、productName、files 只含 electron/ 与 package.json）与 `"dist": "electron-builder"`
- 开发依赖加 `electron-builder`
- 说明：`npm run dist` 生成 `dist/*.dmg`（macOS）；产物运行仍假设项目目录存在（后端/前端由壳拉起）

## 四、测试

- 桌面壳为主进程脚本，不做单测（本地人工验证）；回归 `tsc` + `vitest` + E2E（不影响）

## 五、验收

1. `npm run desktop` 打开后，拖窗口到某位置/改大小 → 关闭 → 再开，位置/大小恢复
2. `npm run dist` 能生成安装包（或至少 electron-builder 配置可被解析；若环境无签名则记录为后置）
