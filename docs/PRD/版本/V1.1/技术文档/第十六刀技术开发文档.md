# 第十六刀技术开发文档｜失败可解释（报错对人话）

> 配套：PRD V1.1 §3.4「可理解失败态」；§9「PM 文案用产品语言」。  
> 前置：第十五刀（§5.3 多模型工位）已复验通过；本刀承接「PM 独立走通」体验收口。  
> **先写本文，再写代码。** 改完 commit，停等用户复验。

## 一、阶段目标

让**非技术 PM 在失败时看得懂、知道下一步做什么**；开发者仍能拿到技术原因排查。核心是把「沙箱拒绝: 禁止调用: eval」「流水线卡死超时（304s 无进度），已熔断」这类天书，变成 PM 能懂的人话 + 建议动作。

### 本刀产物

| # | 路径 / 行为 |
| --- | --- |
| 1 | `FactoryRun.failure_code VARCHAR(32) DEFAULT ''` + 幂等迁移 |
| 2 | 新模块 `app/services/failure_reasons.py`：code →（PM 人话, 建议动作）映射 + 测试原因分类器 |
| 3 | 各失败点写入 `failure_code`：测试失败分类、闸门失败、`_mark_failed` 复用已有 code、看门狗 `run_stuck` |
| 4 | `RunOut.failure_code`；前端 `Run` 类型同步 |
| 5 | 前端失败条按角色分显：PM=人话+建议动作；开发者=原始 failure_reason + 失败阶段 |
| 6 | 单测 + `docs/项目状态.md` + 验收目录；仅 Agent造物坊；commit；停 |

### 明确不做

- 不做失败自动重试 / 自动改 prompt 重生成（本刀只解决「看得懂」）
- 不改沙箱规则、不改提示词、不改验收清单
- 不动 AI万物伙伴 / AI造梦机 / 共享层
- 不把完整 prompt、Key 打进前端或失败文案

## 二、现状与缺口

| 问题 | 现状 | 缺口 |
| --- | --- | --- |
| PM 看不懂报错 | `failure_reason` 是原始技术串（`代码测试未通过：沙箱拒绝: 禁止调用: eval`） | 无失败分类、无 PM 话术 |
| 无「怎么办」 | 失败条只有一句报错 | 缺建议动作 |
| 开发者信息不足 | 只展示 reason，阶段有但分散 | 统一保留原始 reason + 阶段 |

## 三、方案

### 3.1 数据

`factory_runs.failure_code VARCHAR(32) DEFAULT ''`，迁移幂等 `ALTER TABLE ... ADD COLUMN failure_code ...`。

code 取值（稳定机器码，前端只认 code 不解析字符串）：

| code | 含义 | PM 话术 | 建议动作 |
| --- | --- | --- | --- |
| `sandbox_blocked` | 用了不安全写法（eval 等） | 生成的内容没过安全检查 | 换个说法再试，或让开发者看原因 |
| `code_syntax` | 语法错 | 生成的代码有问题，跑不起来 | 点「整段重跑」重新生成 |
| `code_guard` | 成品护栏不通过 | 生成的代码有问题，跑不起来 | 点「整段重跑」重新生成 |
| `code_deps` | 依赖缺 | 生成的代码有问题，跑不起来 | 点「整段重跑」重新生成 |
| `code_runtime` | 跑不起来 | 生成的代码跑不起来 | 点「整段重跑」重新生成 |
| `gate_failed` | 自动闸门未通过 | 生成的代码没通过自动检查 | 点「整段重跑」重新生成 |
| `llm_key_missing` | 缺 Key | 模型没连上，多半是 Key 没配好 | 检查 .env 的 LLM_API_KEY 后重试 |
| `llm_call_failed` | 模型调用失败 | 模型没连上，多半是 Key 或网络问题 | 检查 Key 和网络后重试 |
| `unknown_llm_provider` | 模型不认识 | 选的模型不认识 | 换个模型或跟随全局默认再试 |
| `run_stuck` | 看门狗熔断 | 这一步做太久，已经被中断 | 点「整段重跑」重新试一次 |
| `internal_error` | 其它/未知 | 这次没做成功 | 点「整段重跑」再试，或让开发者看看 |

### 3.2 `failure_reasons.py`

```python
PM_TEXT: dict[str, tuple[str, str]] = {...}  # code -> (message, suggestion)

def classify_test_reason(reason: str) -> str:
    # 沙箱拒绝/禁止 → sandbox_blocked；语法错误 → code_syntax
    # 成品护栏 → code_guard；requirements/缺少 → code_deps；其余 → code_runtime

def pm_text(code: str) -> tuple[str, str]:
    return PM_TEXT.get(code, PM_TEXT["internal_error"])
```

### 3.3 失败点接线

- `engine._run_tests`：`run.failure_code = classify_test_reason(reason)`（同时保留 `failure_reason` 原文）
- `engine.advance` 闸门失败：`run.failure_code = "gate_failed"`
- `engine._mark_failed(session, run_id, code, message)`：`run.failure_code = code`（`code` 已是机器码）
- `watchdog.check_stuck_runs`：经 `_mark_failed(..., "run_stuck", ...)` 自动带上

### 3.4 前端

- `RunOut` / `Run` 增加 `failure_code: string`（旧 Run 为空串 → 走 `internal_error` 兜底）
- 失败条（中栏红条）：
  - **PM**：`⚠️ {message}` + 次行 `{suggestion}`（人话，不含技术词）
  - **开发者**：`⚠️ {原始 failure_reason}` + 次行 `阶段：{阶段}`（保留技术细节）
- `pm_text` 逻辑放前端 `factory.ts`（或轻量内联），只做 code→文案映射，不复刻后端分类逻辑

## 四、测试

- 后端：`test_failure_reasons.py`——`classify_test_reason` 各分支、`pm_text` 兜底
- 后端：`test_engine.py` / 既有失败用例断言 `failure_code` 非空且正确
- 前端：`factory.test.ts` 补 `pm_text` 映射用例（若放 factory.ts）
- 回归：`pytest` 全量 + `tsc` + `vitest` + E2E 1/1

## 五、验收

1. 用「小工具」类 idea 触发一次 eval 失败（或 mock 造一条 `sandbox_blocked`）：PM 视图看到人话「生成的内容没过安全检查」+ 建议动作，**不出现 eval / sandbox** 字样
2. 切开发者视图：看到原始 `沙箱拒绝: 禁止调用: eval` + 失败阶段
3. 旧失败 Run（无 failure_code）在 PM 视图显示兜底文案，不报错不空白
4. 其它失败分类（卡死/模型未连上）文案抽查
