# 第二十刀技术开发文档｜多 Agent 分工看板（§5.3 增强）

> 配套：PRD V1.1 §5.3「多 Agent 分工看板」。  
> 前置：第十九刀（定时无人值守）已复验通过。  
> **先写本文，再写代码。** 改完 commit，停等用户复验。

## 一、阶段目标

把流水线各阶段当作「工位（Agent）」，用**看板**展示当前 Run 在每个工位的状态与产物，让 PM/开发者一眼看清「工厂现在做到哪、卡在哪、由哪个模型在做」。不改流水线架构（仍是串行），只做**可视化看板**。

### 本刀产物

| # | 路径 / 行为 |
| --- | --- |
| 1 | 中栏顶部 `SessionRail` 增加「紧凑 / 看板」切换 |
| 2 | 看板视图：阶段卡片流，每卡展示阶段名、状态图标（✓ 完成 / 进行中 / 等待 / 失败）、当前模型（dev 可见）、阶段产物摘要（有产物时） |
| 3 | 状态复用 `stageStatus`；产物摘要复用 `run.evidence`；不新增后端 |
| 4 | 单测（纯函数如 `stageStatus` / 摘要提取）+ 回归 + commit 停 |

### 明确不做

- 不做真正的多 Agent 并行架构（串行流水线保持不变）
- 不改后端、不改状态机、不改产物
- 不动 AI万物伙伴 / AI造梦机 / 共享层

## 二、现状与缺口

| 问题 | 现状 | 缺口 |
| --- | --- | --- |
| 只有紧凑进度条 | `SessionRail` 一排小药丸 | 信息密度低，看不清「哪个工位卡住/产出什么」 |
| 阶段与产物割裂 | 产物在右栏，进度在中栏顶部 | 看板把两者对齐到一起 |

## 三、方案

### 3.1 前端结构

`SessionRail` 内：
- 头部加两个小按钮：「紧凑」「看板」；状态存 `useState`（会话内）。
- 看板模式：`STAGE_ORDER`（PM 用 `PM_STAGE_ORDER`）映射成卡片流，横向滚动或纵向列表。

### 3.2 看板卡片

每张卡：
- 阶段名（`STAGE_CN`）
- 状态：`stageStatus(current, s)` → ✓（done，绿）/ ⚙️ 进行中（brand 色 + 脉冲点）/ 等待（muted）/ ❌（failed，红）
- 当前模型：仅 `role === "dev"` 且本阶段为当前阶段时显示 `run.llm_provider || "跟随全局"`（复用 15 刀数据）
- 产物摘要：`run.evidence` 中 `stage === s` 的第一条 `title`（无则空）

### 3.3 复用

- `stageStatus` 已在 page.tsx，抽成纯函数导出（或直接在组件内复用）
- 不新增后端接口、不改 `deriveMessages`

## 四、测试

- 前端：`stageStatus` 边界（已完成/当前/未来/失败）已有或补 1 条；产物摘要提取纯函数补 1 条
- 回归：`tsc` + `vitest` + E2E 1/1（后端无改动）

## 五、验收

1. 中栏顶部能切「紧凑 / 看板」。
2. 看板里每个阶段有状态图标；当前阶段高亮 + 脉冲；失败阶段标红。
3. dev 视图当前阶段显示模型（mock / deepseek / 跟随全局）；PM 视图不显示模型。
4. 有产物的阶段显示产物标题。
