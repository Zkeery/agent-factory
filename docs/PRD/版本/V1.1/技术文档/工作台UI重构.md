# 工作台 UI 重构

日期：2026-10-05。所属版本：V1.1。范围：将新增的需求纠错、真实任务验证、失败改版和完整交付能力整理为清楚的工作界面。本轮仅修改前端视觉与信息层级，沿用前序 [本地验证与交付增强](本地验证与交付增强.md) 的 API、鉴权和生成管线。线上托管仍为后续范围。

## 界面与行为

| 区域 | 已实现行为 |
| --- | --- |
| 视觉基础 | 浅灰画布 `#f7f8fa`、白色表面、正文 `#182230`、说明 `#737f91`、边界 `#e7eaf0`、主色 `#2563eb`；Lucide 图标；统一卡片、按钮、输入框与状态标签。卡片圆角 12px，控件 8–10px。 |
| 创建首页 | 居中展示想法输入、模型选择和创建动作；提供「把访谈变成需求」「收集读者的想法」「管理自己的小项目」三张模板卡，点击填入可编辑的想法，不立即创建。未选中 Run 时隐藏无内容的资料栏。 |
| 项目导航 | 按已有项目和 Run 数据搜索，保留项目选择、创建与角色切换。选中 Run 后不再显示新建想法输入，避免把需求补充误当新项目。 |
| 当前任务 | 四步进度为「需求共创 / 构建应用 / 任务验证 / 交付迭代」，当前阶段卡片与下一步动作优先，生成过程和历史记录折叠。原细阶段与状态机继续有效。 |
| 构建前审核 | 「需求文档与纠错 / 验收场景」页签分开呈现；需求纠错与决策修改入口清晰可见。决策可修改范围沿用现有接口约束；场景未保存时仍禁止确认构建。 |
| 真实任务验证 | 每个场景完整展示输入、预期和实际观察；顶部统计真实记录数、通过数、未通过数。空观察不计作已记录或已通过，失败项明确标识。 |
| 保存与改版 | 保存试用记录属于草稿动作；未通过场景可带入改版表单，确认修改要求后创建子版本。保留原请求、错误处理与幂等请求标识行为。 |
| 最终交付 | 所有场景通过且完成基础清单后才能正式验收；交付包展示代码、说明、验收材料。待验收按钮为「下载待验收版」，已交付按钮为「下载完整交付包」。 |
| 版本摘要 | 显示初版/修改版、当前阶段和本次修改内容，帮助用户辨认正在处理的版本；历史记录与产物仍可追溯。 |
| 手机与窄屏 | 当前任务占据主要空间，导航与项目资料通过抽屉打开和关闭；桌面选中 Run 后仍为三栏，不新增第四栏。 |

## 代码归属

| 文件 | 职责 |
| --- | --- |
| `frontend/app/globals.css` | 浅色 tokens、工作台布局和统一卡片/表单/按钮/状态样式 |
| `frontend/app/page.tsx` | 导航、真实搜索、创建与任务分流、审核页签、当前阶段动作、版本摘要、资料栏与移动端抽屉 |
| `frontend/components/WorkspaceHome.tsx` | 创建首页、三场景模板和四步进度 |
| `frontend/components/RunImprovements.tsx` | 需求纠错、任务编辑、真实验证、记录回看、失败改版和交付包工作卡 |

本轮不改变服务端数据模型、接口请求或响应。UI 继续使用已有的用户认证、Run 所有权、PRD 版本确认与验收约束；场景模板和进度展示不等于新增生成能力或通过质量评测。
