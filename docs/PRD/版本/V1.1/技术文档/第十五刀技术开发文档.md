## 一、阶段目标

把「全局 .env 绑死一个 LLM」升级为 **Run 级可选模型 + 开发者可看见用了谁 + 可选 PRD 草稿双模对比**。这是 §5.3「多模型对比工位」的第一切片，不是完整多厂商矩阵，也不是商业化计费。

### 本刀产物

| # | 路径 / 行为 |
| --- | --- |
| 1 | `FactoryRun.llm_provider`（`mock` / `deepseek` / 空=跟随全局设置）+ 轻量迁移 |
| 2 | `get_llm(provider=...)`；引擎按 **本 Run** 的 provider 取客户端 |
| 3 | `GET /api/v1/llm/profiles`：返回可用画像（不回显 Key）；`CreateRunRequest.llm_provider` 可选 |
| 4 | `POST /api/v1/llm/compare-prd`：同一 idea（+ 可选已答决策）并行/串行产出 mock 与（若有 Key）deepseek 两份 PRD 草稿对比 |
| 5 | 前端：新建想法时可选手动模型（开发者默认可见；PM 可折叠/默认跟随）；右栏质量区展示本 Run `llm_provider` + 实际 `llm_model` |
| 6 | 开发者入口「对比 PRD 草稿」：调用 compare-prd，并排展示两份摘要（不自动开新 Run） |
| 7 | 单测 + `docs/项目状态.md` + 本验收目录；仅 stage 造物坊；commit；停 |

### 明确不做

- 不定时无人值守、不多 Agent 看板、不做接近上线/商业化（§5.3 其它项后置）
- 不接第二家云厂商 SDK（本刀只认 `mock` + 现有 OpenAI 兼容 `deepseek` 配置）
- 不在对比接口里自动创建正式 Run / 不自动写工作区
- 不改登录、验收闸门、沙箱、试衣/视频护栏
- 不改 AI万物伙伴 / AI造梦机 / 共享层
- 不把 Key、完整 prompt 打进前端或对比响应

## 二、现状与缺口

| 问题 | 现状 | 缺口 |
| --- | --- | --- |
| 全局绑死 | `settings.llm_provider` + `get_llm()` 无 Run 参数 | Run 级字段与引擎接线 |
| 不可见 | 前端不知道本轮用了 mock 还是 deepseek | RunOut / 质量区暴露 provider+model（model 名可公开，Key 不可） |
| 无对比 | 换模型只能改 .env 再整段重跑 | 轻量 compare-prd 工位，选优后再正式开 Run |

## 三、方案

### 3.1 数据

`factory_runs.llm_provider VARCHAR(32) DEFAULT ''`：

- `''` / `null`：跟随 `settings.llm_provider`（兼容旧 Run）
- `mock`：强制 MockLLM
- `deepseek`：强制 RealLLM（缺 Key → 创建时 400 或 advance 时既有 `llm_key_missing`）

迁移：`_migrate_schema` 幂等 `ALTER TABLE ... ADD COLUMN llm_provider ...`。

可选只读快照字段（推荐一并做，便于复盘）：`llm_model_snapshot VARCHAR(64) DEFAULT ''` —— 本 Run **首次真正调用模型时**写入当时的 `settings.llm_model` 或 `mock`；不随后续改 .env 而变。

### 3.2 `get_llm(provider: str | None = None)`

```text
effective = (provider or settings.llm_provider).strip().lower()
mock → MockLLM
deepseek → RealLLM
其它 → AppError unknown_llm_provider
```

`engine` 凡 `get_llm()` 处改为 `get_llm(run.llm_provider or None)`。

### 3.3 API

#### `GET /api/v1/llm/profiles`

鉴权同 runs。响应示例：

```json
{
  "default_provider": "deepseek",
  "profiles": [
    {"id": "mock", "label": "本地 Mock（零成本）", "available": true, "model": "mock"},
    {"id": "deepseek", "label": "DeepSeek（.env）", "available": true, "model": "deepseek-chat"}
  ]
}
```

`available=false` 当 deepseek 且 `llm_api_key` 为空（前端禁用选项并提示去配 Key，**不**回显 Key）。

#### `CreateRunRequest` 增补

- `llm_provider: str | None = None` —— 非法 id → 400；deepseek 且无 Key → 400 `llm_key_missing`；省略则存 `''`（跟随全局）。

`RunOut` / 列表摘要至少增加：`llm_provider: str`、`llm_model: str`（快照或当前解析结果）。

#### `POST /api/v1/llm/compare-prd`

Body：

```json
{ "idea": "...", "decisions": [ {"code":"...", "question":"...", "answer":"..."} ] }
```

行为：

1. 始终跑 mock → `generate_prd`
2. 若 deepseek profile available，再跑 RealLLM → `generate_prd`（失败则该分支 `error` 字段，不拖垮整响应）
3. 返回：

```json
{
  "variants": [
    {"provider":"mock","model":"mock","prd":{...},"prompt_tokens":0,"completion_tokens":0,"error":null},
    {"provider":"deepseek","model":"deepseek-chat","prd":{...},"prompt_tokens":123,"completion_tokens":456,"error":null}
  ]
}
```

- 不落库、不创建 Run  
- 超时沿用 `llm_timeout`；可串行调用以降低并发压测风险（文档约定串行即可）  
- PM 也可调（只读对比）；正式开跑仍走 create run

### 3.4 前端

| 区域 | 行为 |
| --- | --- |
| 新建想法 | 增加「模型」下拉：跟随默认 / Mock / DeepSeek（不可用项 disabled）；值传入 `createRun` |
| 右栏质量（开发者） | 展示 `llm_provider` + `llm_model` |
| 开发者工具区 | 「对比 PRD 草稿」：输入当前 idea（或空态输入框）→ 调 compare-prd → 两列卡片展示 title/summary 等关键字段 |

PM 视图：可不展示对比入口；新建时默认「跟随全局」，避免增加决策负担。

### 3.5 测试

- `test_llm_profiles.py`：无 Key 时 deepseek `available=false`；有 Key（monkeypatch）为 true；响应无 api_key 字样  
- `test_run_llm_provider.py`：create 带 `mock` → Run 字段为 mock；engine 侧可用 monkeypatch 断言 get_llm 收到的 provider  
- `test_compare_prd.py`：至少返回 mock 分支；deepseek 无 Key 时 variants 仅 mock 或 deepseek 带 error（与实现约定一致并写进用例）

## 六、风险

- RealLLM 对比会花用户额度：UI 标明「对比会调用已配置模型，可能产生费用」。  
- 旧 Run `llm_provider=''` 必须仍跟随全局，行为与改前一致。  
- compare 与正式产线是两条路径：对比满意后仍需用户点新建/开跑，避免静默落盘。
