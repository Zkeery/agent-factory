## 三、方案

### 3.1 判定 `_is_tryon_idea`

想法或 PRD 含：试衣 / 试穿 / 换装 / 虚拟试穿 / try-on / virtual try-on，或「上传照片看上身效果」类表述 → 试衣类。

与视频并列：`generate_code` 先判 tryon，再判 video，再默认文本演示。

### 3.2 `code.md` 硬约束（对标第十二刀 §3.4）

1. 主路径必须让用户得到**可查看预览图**（HTML `<img>` / `/preview.png` / `image_base64` / `image/png`）。
2. **禁止**唯一产物为「仅提示词 / 换装方案 / 步骤文案」；文案最多作附注。
3. 无云端图像 API Key：必须用 Pillow（或等价）本地合成演示图；`POST /generate` 仍 HTTP 200。
4. 页面标明「试穿预览」；本地合成写「本地演示图」。

### 3.3 mock tryon 模板

- GET `/`：可选上传 + 衣服描述 → 点「生成试穿预览」→ `<img>` 展示结果。
- `POST /generate`：返回 `result` + `image_base64`（或 `preview_url: /preview.png`）；Pillow 画演示图（人物剪影色块 + 服装色条 + 文案「本地演示图」）。
- requirements：`fastapi` / `uvicorn` / `pillow` / `python-multipart`。

### 3.4 护栏

`check_tryon_produces_image(source)`：

- 源码像试衣类（关键词同上），且**缺少**强出图标记（`image_base64` / `image/png` / `/preview.png` / `Image.new` / `from PIL` / `PIL`），同时带长文换装/提示词回落特征 → 失败。
- 仅有上传预览用的 `<img`、无服务端出图字段，视为未满足。
- `testing.run_tests` 在 JS 护栏后接入；失败文案前缀 `成品护栏:`。

### 3.5 热修当前试衣成品

若 `backend/data/code/931100bd-e42f-4582-972e-8035712dd9bf`（或以 `lsof -iTCP:8007` 为准）仍在：替换 `app.py` 为符合约束的演示版，更新 requirements；杀掉占用 8007 的旧进程并用 uvicorn 在该目录重新拉起；`curl POST /generate` 断言含图片字段。
