# 第十刀技术开发文档｜决策台账与运行说明右栏一等公民

> 配套：PRD V1.1 §2.3 产物、§4.1 MVP 成功定义第 4 条、§9 界面原则。  
> 前置：第九刀（预览运行态 + `prefer_open_url`）已复验通过。  
> **先写本文，再写代码。** 不进入 §5.3 增强（多模型 / 无人值守 / 多 Agent 看板）。

## 一、阶段目标

让产品经理在右栏就能看见：

1. **决策台账**：本轮问过什么、人怎么答的（对齐 §4.1「决策台账完整」可被看见，而不只埋在闸门证据里）。
2. **运行说明**：README / 启动步骤可点开阅读（对齐 §2.3「运行说明」），不必切到开发者看代码气泡。

### 本刀产物

1. 右栏固定「决策台账」区块（数据来自已有 `run.decisions`，不另造表）。
2. 后端在代码阶段写入 `kind=readme` 产物（README 全文）；部署阶段 `deploy` 产物 content 写入 `start.sh` + 验收清单全文（不再只有一句摘要）。
3. `PM_ARTIFACT_KINDS` 增加 `readme`；台账区块 PM/Dev 均可见。
4. 单测 + 更新 `docs/项目状态.md`；验收目录 `验收证据/第十刀/`。
5. commit 后停等复验——**不自动开第十一刀 / §5.3**。

### 明确不做

- 预览 iframe 内嵌（第九刀已后置）
- 预览进程跨后端重启保活
- 改流水线阶段、改决策问答交互本身
- 动 AI万物伙伴 / AI造梦机 / 共享层

## 二、现状与缺口

| 能力 | 现状 | 缺口 |
| --- | --- | --- |
| 决策数据 | `Decision` 表 + `RunOut.decisions`；对话里有决策卡 | 右栏无台账；闸门证据里的台账 kind=gate，PM 被第七刀过滤掉 |
| README | 写到 `data/code/{run}/README.md` | **未**进 Evidence / 产物列表 |
| 运行说明 | deploy 产物标题在，content 仅一句「已生成」 | PM 点开看不到启动命令与清单 |
| PM 产物白名单 | `prd` / `deploy` | 无 `readme`；台账未独立呈现 |

## 三、方案

### 3.1 决策台账（前端为主）

- 右栏「预览」面板在产物列表上方（或下方固定区）增加 **决策台账**。
- 数据：当前选中 Run 的 `decisions[]`（已有字段：`code` / `question` / `answer` / `status` / `is_critical`）。
- 展示：列表；已答显示答案；未答显示「待回答」；关键决策可标「关键」。
- 无决策时：不占版面或一行「暂无决策」。
- **不**把台账塞进 gate 证据冒充产物；避免与第七刀「PM 隐藏闸门证据」冲突。

纯函数建议（便于单测）：

```ts
export function summarizeDecisionLedger(decisions: Decision[]): {
  total: number; answered: number; pending: number; lines: { code: string; question: string; answer: string | null; critical: boolean }[];
}
```

### 3.2 运行说明产物（后端）

1. `evidence.add_evidence` 的 `kind_map` 增加：`"readme" -> "readme"`（或允许直接传 kind）。
2. 代码写入磁盘后：`add_evidence(..., stage="readme", title="运行说明", content=readme全文)`。  
   - 若 README 为空，写占位：「（模型未给出 README，请查看代码目录。）」
3. `deploy.generate_deploy` 之后：读取 `start.sh` 与验收清单文件，拼成 markdown 写入 deploy 产物 content（覆盖原先一句摘要）。
4. 列表/详情 API 无需改契约；`Artifact.kind` 多一个 `readme`。

### 3.3 前端产物过滤

```ts
export const PM_ARTIFACT_KINDS = ["prd", "deploy", "readme"] as const;
```

- 开发者仍看全部（含 code/gate）。
- 产物预览区：`readme` / `deploy` / `prd` 继续按文本渲染即可。

## 四、测试

后端：

1. mock 跑到 code/deploy 后，artifacts 中存在 `kind=readme` 且 content 非空；`kind=deploy` content 含 `start.sh` 或启动关键字。
2. 回归：既有 gate / accept / workspace 测试仍绿。

前端：

1. `summarizeDecisionLedger`：空 / 部分已答 / 全答。
2. `filterArtifactsForRole`：PM 含 `readme`，仍不含 `code`/`gate`。

## 五、验收标准（给产品经理）

1. 硬刷新 http://127.0.0.1:3010/ ，打开已有决策的 Run：右栏能看到决策台账问答，不必切开发者。
2. 交付或已生成代码的 Run：产物列表出现「运行说明」；点开能看到 README 正文。
3. 「部署 / 运行说明」类产物点开能看到启动命令或验收清单正文（不再只有「已生成」）。
4. 产品经理视图仍看不到原始代码与闸门打分细节。

## 六、风险与回退

- 旧 Run 无 `readme` 产物：可接受；仅新跑或重跑后有。台账仍可从 `decisions` 显示。
- deploy content 变长：详情接口已返回全文，注意前端预览滚动即可。
- 回退：去掉右栏台账区块；`PM_ARTIFACT_KINDS` 去掉 `readme`；停止写入 readme 证据。

## 七、实现顺序

1. 写本文并建 `验收证据/第十刀/`
2. 后端 readme + enrich deploy content + 测试
3. 前端台账区块 + PM 白名单 + 单测
4. 更新 `docs/项目状态.md`
5. commit，停等复验
