# 第十八刀技术开发文档｜生成稳定性（剥杂质 + 语法错误重试一次）

> 前置：V1.1 核心 MVP 已收尾（第十七刀复验通过）。  
> 触发：真实模型偶在代码块夹带「（见上）」等非代码文字，导致语法错误 → PM 需手动整段重跑。  
> **先写本文，再写代码。** 改完 commit，停等用户复验。

## 一、阶段目标

降低真实模型「生成抽风」对 PM 的打扰：**能自动清理就清理，清不掉就自动重试一次**，两次都失败才判闸门失败。

### 本刀产物

| # | 路径 / 行为 |
| --- | --- |
| 1 | `parsing.parse_code`：app 块剥掉纯非 ASCII 备注行（如「（见上）」「（同上）」，无任何 Python 代码的行） |
| 2 | `engine.BUILDING`：写盘后内联 `py_compile`；语法错误则带修正提示重生成一次 |
| 3 | 单测 + 回归 + commit 停 |

### 明确不做

- 不做无限重试（本刀只重试一次；两次都失败仍判闸门失败）
- 不改模型、不改沙箱、不改测试工序结构（`testing.run_tests` 保持确定性）

## 二、现状与缺口

| 问题 | 现状 | 缺口 |
| --- | --- | --- |
| 模型夹带非代码文字 | `parse_code` 只剥 markdown 围栏，不剥纯中文备注 | 「（见上）」直接进 app.py → SyntaxError |
| 语法错误只报不改 | TESTING `py_compile` 失败即 `gate_failed` | 无自动重试，PM 手动整段重跑 |

## 三、方案

### 3.1 剥杂质（parsing.py）

`parse_code` 解析出 `app` 块后，逐行过滤：
- 一行若 **ASCII 部分为空**（去掉所有 ASCII 后 trim 为空）且 **非 ASCII 部分非空**，视为纯中文备注 → 跳过。
- 其余行保留（含 `#` 注释、含中文的字符串字面量行等）。

示例：`（见上）` 的 ASCII 部分为空、非 ASCII 部分为「见上」→ 剥掉；`return {"result": "错误"}` 的 ASCII 部分非空 → 保留。

只作用于 `app` 块；`requirements` / `readme` 不动。

### 3.2 语法错误重试一次（engine.py）

`BUILDING` 动作生成代码并写盘后：
1. `py_compile` 检查 app.py。
2. 若语法错误：用 `run.idea + "（务必只输出语法正确的 Python 代码，禁止夹带任何非代码文字）"` 重新 `generate_code` 一次，覆盖写盘。
3. 第二次仍错 → 照常进入 TESTING，由 `py_compile` 判 `gate_failed`（不再重试）。

证据（code 产物）以**最终写盘的代码**为准。

## 四、测试

- `test_parsing.py` 或现有解析测试：`（见上）` 行被剥掉、含中文字符串的合法行保留。
- `test_engine.py`：mock `generate_code` 第一次返回语法错误、第二次返回合法代码 → BUILDING 后 app.py 可 compile；两次都错 → TESTING 判失败。
- 回归：`pytest` 全量 + `tsc` + `vitest` + E2E 1/1。

## 五、验收

1. 用真实模型跑「做个计算器」类想法，连续几次不应再出现「（见上）」式语法错误。
2. 若第一次生成仍有语法错误，自动重试一次后通过（或两次都错才判失败）。
