# 第九刀技术开发文档｜预览运行态收口

> 配套：`docs/PRD/版本/V1.1/PRD.md` §4.1（可本地启动）、§9（产物与预览不藏气泡）。
> 前置：第八刀已复验通过；热修 `52d9ab5`（失败展示真实错误）。
> **先写本文，再写代码。** 不实现 §5.3 增强项。

## 一、阶段目标

第八刀已做到「启动前必须确认」，但预览仍是「点一下 `window.open` 就结束」：

1. 刷新页面后不知道预览是否还在跑；
2. 没有停止入口，端口容易残留；
3. 运行地址只闪现在新窗口，右栏预览区无运行态。

本刀把「本地预览」收成可观察、可打开、可停止的运行态，对齐 MVP「本机按说明能启动」的人感闭环。

### 本刀产物

1. 前端：`getAppStatus`；预览栏运行态（地址 / 打开 / 停止）
2. 切换 Run 或可预览阶段时轮询/拉取 `GET /runs/{id}/app-status`
3. 启动成功后右栏立即展示运行中，而不是只依赖弹窗
4. 纯函数单测 + 必要后端回归（若缺 status 用例则补一条）
5. 更新 `docs/项目状态.md`、`docs/README.md`；验收说明目录 `验收证据/第九刀/`

### 明确不做

- §5.3（多模型工位、定时无人值守、多 Agent 看板、公网上线）
- 改写 runner 端口策略 / 沙箱隔离大改
- 把预览嵌进 iframe（跨域与 cookie 风险后置）
- 付费/对外发送确认（§8 其余条款）

## 二、现状与缺口

| 能力 | 现状 | 缺口 |
| --- | --- | --- |
| 启动 | `POST .../start` + 授权闸门 | 有 |
| 停止 | `POST .../stop` 已存在 | 前端未接 |
| 状态 | `GET .../app-status` 已存在 | 前端未封装、未展示 |
| 右栏 | 「打开预览」按钮 | 无 running/url/停止 |

## 三、接口（沿用，不新开权限模型）

### `GET /api/v1/runs/{run_id}/app-status` → `AppRunOut`

```json
{ "running": true, "url": "http://127.0.0.1:8002", "port": 8002 }
```

未运行：`running=false`，`url/port` 为 null。

### `POST /api/v1/runs/{run_id}/stop` → `AppRunOut`

停止后应返回 `running=false`。本刀若发现返回体不一致，仅做最小修正。

### `POST .../start`

行为不变（仍走第八刀 exec 授权）。成功后前端用返回体更新运行态，并可继续 `window.open`。

## 四、前端

1. `frontend/lib/factory.ts`
   - 新增 `getAppStatus(id)`
   - 可选纯函数 `summarizeAppStatus(status)`（文案：「未运行」/「运行中 · 端口 x」），便于单测
2. `PreviewPanel`（右栏「本地运行」）
   - `canRun` 时：挂载/切换 run 拉取 status；运行中每 5s 轻量轮询（离开面板或 `!canRun` 停止）
   - 展示：未运行时保留「打开预览」；运行中显示 url（可点「在浏览器打开」）+「停止预览」
   - 停止中按钮 loading；失败 `alert` 真实错误（沿用 `52d9ab5` 解析）
3. 启动成功：`setAppStatus(result)`，避免必须等下一轮轮询才看到地址
4. **不改**授权确认卡逻辑；未授权仍先弹第八刀确认

## 五、测试

前端（`factory.test.ts`）：

1. `summarizeAppStatus`：未运行 / 运行中文案
2. 若有「是否显示停止按钮」类纯函数一并测

后端（可选增强）：

1. 已授权 delivered run：`start` → `app-status.running==true` → `stop` → `running==false`（可 mock runner 或沿用现有手法）
2. 全量 pytest 仍须绿

回归：`npx vitest run` + `tsc --noEmit`。

## 六、验收标准（给产品经理）

1. 硬刷新 http://127.0.0.1:3010/ ，已交付 Run：确认后打开预览 → 右栏出现运行中地址。
2. 点「在浏览器打开」能再次打开同一地址。
3. 点「停止预览」后右栏回到未运行，原端口不可再访问（或 status 为未运行）。
4. 刷新页面后，若后端进程仍在，右栏应恢复为运行中（依赖 app-status）；若后端重启导致进程表丢失，显示未运行可接受。
5. 未到可预览阶段时，不出现停止/地址区。

## 七、风险与回退

- runner 内存表：后端进程重启后 status 会丢——文案不承诺跨后端重启保活。
- 轮询过频：固定 ≥5s，仅 `running` 或刚启动后短时轮询。
- 回退：去掉右栏运行态 UI 与 `getAppStatus` 调用即可；后端接口保留。

## 九、热修：打开地址优先可读入口（2026-09-23）

**现象**：部分成品只有 API（如 `POST /generate`），根路径 `/` 返回 FastAPI `404 JSON`；「在浏览器打开」落到 `http://127.0.0.1:port/` 像坏了。

**改动**：`runner.prefer_open_url(base)` —— 探测顺序：HTML `/` → `/docs` → `/redoc` → 退回 base。`start_app` / `app_status` 返回的 `url` 经此函数。

**验收**：纯 API Run 打开应为 `…/docs`（Swagger）；有 HTML 首页的仍开根地址。
