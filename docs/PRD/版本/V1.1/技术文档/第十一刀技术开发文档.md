## 一、阶段目标

让工厂**新生成**的本地成品，在默认预览路径上更接近「能点、能演示」：

1. 无 `DEEPSEEK_API_KEY` 时，主路径仍返回可读结果（HTTP 非 5xx），不把演示卡死。
2. 若成品自带简单网页（菜单 / 对话 / 购物车一类），**对话推荐必须能落到可加购的真实菜单项**，禁止助手编菜单外菜名却不加购。
3. 嵌在 Python 字符串里的前端 JS，不得因 `\n` 被 Python 解释成真换行而整页脚本挂掉。
4. 上述规则进入：生成 Prompt、mock 模板、落盘后的静态护栏（测试工序可失败并写清原因）。

## 二、现状与缺口

| 能力 | 现状 | 缺口 |
| --- | --- | --- |
| 代码 Prompt | 要求 FastAPI + `POST /generate` + 无 Key 时 **HTTP 500** | 与 `http_main_smoke`「非 5xx」冲突；未约束 HTML/JS 嵌套与「推荐必须可加购」 |
| mock 成品 | 纯 API，无页面；无 Key 返回 `error` 字段但是 200 | 演示弱；不能覆盖「页面 JS 挂死」类回归 |
| 测试工序 | `py_compile` + smoke import + 启动探测 + `/generate` 烟测 | 捕不到「JS 在 Python 字符串里被吃换行」——`py_compile` 仍通过 |
| 预览注入 Key | `runner._child_env` 注入工厂 LLM Key | 用户手动 uvicorn 无 Key 时仍可能 500；Prompt 仍教模型返回 500 |

实机教训（扫码点单类成品，2026-09-24）：

1. `app.py` 用普通 `"""..."""` 包整页 HTML，JS 里写 `"\\n"` 意图变成字符串换行，实际变成 JS 源码换行 → 整页脚本 SyntaxError → 按钮全死。
2. 助手用 DeepSeek 自由推荐「辣子鸡」，菜单数组里没有该项 → 无法加购。
3. 聊天只回文本，不驱动 `cart` / 不调加购 API → 「完全不在一个频道」。

## 三、方案

### 3.1 Prompt 硬约束（`prompts/code.md`）

在现有「三块输出」结构上追加（中文条目即可）：

1. **无 Key**：缺少 `DEEPSEEK_API_KEY` 时，`POST /generate` 必须 **HTTP 200**，body 形如 `{"result":"..."}`，用本地规则/模板回复；**禁止**故意 5xx。
2. **嵌套前端**：若在 Python 源码内嵌 HTML/JS：
   - 优先：JS 内需要的换行写成 `\\n` 在**最终写入文件的源码**里是两个字符 `\\` + `n`（即 Python 源码中写 `\\\\n` 若用普通拼字符串——文档里用示例说明）；或改用 **raw 三引号** `r"""..."""`；或把 HTML 放到独立逻辑且 JS 字符串不用真实换行打断。
   - 验收口径：浏览器执行 `<script>` 无 SyntaxError。
3. **对话 + 菜单/购物车**：若做点单/推荐类 UI，菜单必须是前端与后端的**同一数据源**；助手只能推荐菜单内菜名；用户确认后必须触发加购（返回结构化 `add_to_cart` 或前端根据菜名匹配 `addCart`）。禁止只聊天不加购。
4. 继续要求存在 `POST /generate`（工厂烟测依赖）；可同时有 `/menu` `/orders` 等，但不取代 `/generate`。

### 3.2 mock 模板升级

`mock_llm.generate_code` 改为生成「最小可演示」应用，建议包含：

- `GET /`：简单 HTML（想法标题 + 输入框 + 发送 + 结果区）；可选一行「示例菜单」按钮调用加购演示（点单类 idea 时）。
- `POST /generate`：无 Key → 200 + 本地回声/推荐；有 Key → 可仍走 OpenAI 兼容调用（mock 为保持简单，**允许始终本地回落**，不强制真调模型）。
- HTML/JS **转义安全**（本刀单测锁定）。
- README 写明：模拟/本地回落；支付若存在则标明「模拟」。

不必在 mock 里复刻完整扫码点单；要覆盖护栏与「可点发送」。

### 3.3 静态护栏 `codegen_guard`

```python
def check_embedded_js_safety(app_py_source: str) -> tuple[bool, str]:
    """探测高危：非 raw 的三引号字符串中，<script> 内出现「引号字符串跨真实换行」。"""
```

启发式足够（不必上完整 Python AST 解释器）：

1. 找出非 `r`/`R` 前缀的 `"""..."""` / `'''...'''` 块（简易扫描，注意逃逸）。
2. 若块内同时含 `<script` 与 `</script>`：检查 script 段内是否存在奇数引号跨越 raw newline 的典型破损；或直接禁止 script 内出现「`"` + 真换行 + 非注释内容 + `"`」模式。
3. 失败信息示例：`嵌入的 JS 字符串含未转义换行（常见于 Python 普通三引号里写 \\n）。请改用 raw 字符串或把 \\n 写成 JS 字面 \\n。`

接入：`testing.run_tests` 在 `py_compile` 成功后、沙箱 `check_source` / `run_smoke_import` 前调用；失败返回 `成品护栏: …`，便于闸门展示。

可选（本刀不做也行）：写盘前自动改写——风险高于检测，**本刀只检测不改写**，避免误伤合法多行 HTML。

### 3.4 测试

后端：

1. `test_codegen_guard_rejects_broken_js_newline`：构造含破损嵌入 JS 的源码 → `ok is False`。
2. `test_codegen_guard_accepts_raw_or_safe`：raw 三引号或正确 `\\n` → 通过。
3. `test_mock_code_passes_guard_and_compile`：`generate_code` 产物写入临时文件 → compile + guard。
4. 回归：既有 testing / runner / accept 等测试仍绿。

前端：本刀无强制 UI 改动（除非 README 预览文案需区分「模拟」——不强制）。

## 四、风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 护栏误杀含多行模板的合法 HTML | 只在 `<script>` 内查「字符串跨真换行」；先上启发式单测调准 |
| Prompt 变严导致模型更啰嗦/偶发不按三块输出 | 保持三块标记要求不变；结构解析逻辑不动 |
| 历史 Run 仍是坏的 | 文档写明需「重新生成」；不在本刀批量改 data/code |

回滚：还原 `code.md` / `mock_llm.py` / 去掉 guard 接入即可；data 无迁移。
