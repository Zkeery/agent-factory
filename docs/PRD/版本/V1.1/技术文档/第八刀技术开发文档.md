> 前置：第七刀（PM/开发者信息密度）已提交 `ced5b15`。

## 一、阶段目标

把 PRD §8 的「写工作区 / 执行启动」从口头约定变成**可强制的人审闸门**：

1. 本地预览启动（`POST /runs/{id}/start`）默认必须先授权 `exec`。
2. 若项目已绑定 `workspace_path`，把本轮生成代码同步到该目录前必须先授权 `write`。
3. **开发者**可勾选「本 Run 始终允许」，同一次 Run 内后续写盘/启动不再弹确认。
4. **产品经理**可以单次确认写盘或启动，但**不能**勾选「始终允许」（危险调试能力只给开发者）。

### 本刀产物

1. Run 级授权状态（持久化）+ 授权 / 同步 API
2. `start` 接口强制校验 `exec`（或 always）
3. 前端确认卡（角色差异）+ 绑定工作区后的「同步到工作区」入口
4. pytest + 前端单测
5. `docs/项目状态.md` 更新；验收说明目录预留在 `docs/PRD/版本/V1.1/验收证据/第八刀/`

### 明确不做

- 真实 shell 任意命令、安装依赖到用户全局环境
- 付费/对外发送类确认（§8 其余条款后置）
- §5.3（多模型工位、定时无人值守、多 Agent 看板、公网上线）
- 改动视觉大改版；不碰 AI万物伙伴与共享层

## 二、现状与缺口

| 能力 | 现状 | 缺口 |
| --- | --- | --- |
| 工作区绑定 | 项目字段 `workspace_path`，前端可保存路径 | 只存路径，不落盘 |
| 生成代码 | 写在工厂 `backend/data/code/{run_id}/` | 未同步到用户工作区 |
| 本地预览 | `start` 直接从 data 目录起 uvicorn | **无确认**，违反 §8 |
| 角色 | PM/Dev 视图已分信息密度 | Dev 专属「始终允许」未做 |

## 三、授权模型

### 3.1 字段（`factory_runs` 增列，轻量迁移）

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `workspace_write_authorized` | bool, default false | 本 Run 已获写盘许可（单次或 always） |
| `workspace_exec_authorized` | bool, default false | 本 Run 已获启动许可 |
| `workspace_always_allow` | bool, default false | 开发者勾选：本 Run 内写盘+启动都视为已授权 |

规则：

- `always_allow=true` 时，读写盘/启动校验一律放行，并回写两个 authorized=true。
- 单次授权只置对应 scope；不自动带 always。
- 授权接口请求体带 `role`（`pm`|`dev`）由前端声明当前视图；**后端以 body.role 为准做能力裁剪**（本地 MVP 无独立 RBAC 表）。`role=pm` 且 `always_for_run=true` → `400 always_not_allowed_for_pm`。

### 3.2 接口

#### `POST /api/v1/runs/{run_id}/workspace/authorize`

```json
{
  "scopes": ["write", "exec"],
  "always_for_run": false,
  "role": "dev"
}
```

- `scopes` 至少一项，元素仅 `write`|`exec`。
- 成功返回更新后的 `RunOut`（需带上三个授权字段，便于前端免再请求）。
- 仅 Run 所属用户可调。

#### `POST /api/v1/runs/{run_id}/workspace/sync`

前置：

1. Run 阶段 ∈ `{gate_passed, awaiting_acceptance, delivered}`（与现有可预览条件对齐）。
2. 关联项目 `workspace_path` 非空，且为绝对路径、目录存在（或可创建最后一级）。
3. `workspace_write_authorized` 或 `workspace_always_allow` 为 true，否则 `403 workspace_write_required`。

行为：把 `data/code/{run_id}/` 下文件**复制**到 `workspace_path`（覆盖同名文件；不删除用户其它文件）。返回：

```json
{ "ok": true, "target": "/abs/path", "files_copied": 3 }
```

路径安全：拒绝 `..` 穿越；拒绝空路径；目标必须 `resolve()` 后仍为声明路径；声明含非法相对逃逸则 400。

#### `POST /api/v1/runs/{run_id}/start`（改）

在现有阶段校验之后增加：若非 `workspace_exec_authorized` 且非 `workspace_always_allow` → `403 workspace_exec_required`，文案提示先确认。

### 3.3 RunOut 增补

```text
workspace_write_authorized: bool
workspace_exec_authorized: bool
workspace_always_allow: bool
```

## 四、前端

1. **本地运行**点击：若 Run 未 exec 授权且非 always → 弹出确认卡（说明将在本机启动预览进程）；确认后先 `authorize({scopes:["exec"], always_for_run, role})` 再 `startApp`。
2. **开发者**确认卡多一个勾选「本 Run 始终允许」；**产品经理**无此勾选。
3. 工作区已绑定且阶段可预览时，预览栏增加「同步到工作区」：未 write 授权则先确认再 sync；已授权直接 sync。
4. API 封装进 `frontend/lib/factory.ts`；确认逻辑尽量纯函数可测（例如 `needsWorkspaceAuth(run, scope)`）。

## 五、测试

后端（新建 `tests/test_workspace_auth.py`）：

1. 未授权 start → 403 `workspace_exec_required`
2. authorize exec 后 start → 200（可用 mock/跳过真实拉起，或按现有 start 测试手法）
3. PM + always_for_run → 400
4. Dev always 后无需再 authorize 即可通过 exec 校验
5. 未授权 sync → 403；授权 write + 临时目录 sync → 文件出现

前端：`needsWorkspaceAuth` / 角色是否展示 always 的单测。

回归：后端全量 pytest；前端 `npx vitest run` + `tsc --noEmit`。

## 六、验收标准（给产品经理）

1. 硬刷新 http://127.0.0.1:3010/ ，待验收 Run 点「本地运行」→ 先出现确认，确认后才启动。
2. 切到开发者，勾选「本 Run 始终允许」后再点本地运行 → 同 Run 内不再弹确认。
3. 产品经理视图看不到「始终允许」。
4. 绑定一个空目录工作区 → 确认写盘 → 同步后目录内出现本轮产物文件（如 `app.py`）。
5. 未确认时 start/sync 应失败提示，不能静默执行。

## 七、风险与回退

- 旧库缺列：沿用 `_migrate_schema` 幂等 `ALTER TABLE`。
- 同步覆盖用户同名文件：文案写明「将覆盖工作区内同名生成文件」；不做全量删除。
- 回退：去掉 start 校验与 sync 路由即可恢复第七刀行为；授权列可留。
