# Agent造物坊 · PRD V1.1

> 定稿日期：2026-09-23  
> 相对 V1.0：收口成功标准、双角色、工作台式工作区、人审闸门；对标 `product-manager-workbench` 的信息架构与主链路，**不**照搬 Electron / Arco / Rust。  
> 决策与进度以 `docs/项目状态.md` 为准；本文只写产品契约。

---

## 1. 目标用户与核心任务

### 1.1 双角色（都要支持）

| 角色 | 是谁 | 核心任务 | 默认看到什么 |
| --- | --- | --- | --- |
| **非技术 PM** | 不会写代码的产品经理 | 把一句话想法推进成「可本地跑起来的小应用」，并完成决策 / 确认 / 验收 | 对话、待办决策、PRD 摘要、预览与验收清单；**不**看工厂仪表盘、原始闸门分数、底层证据堆 |
| **开发者** | 可协作的工程师 / 技术合伙人 | 查看与介入实现产物、复现运行、排查失败、必要时改约束后再跑 | 在 PM 视图之上增加：产物树、代码/日志、阶段证据、闸门明细、重跑与调试入口 |

同一「产品项目」内两种角色共用一套产线与产物；用**视图与权限提示**区分，不拆成两个互不相通的产品。

### 1.2 一句话价值

Agent造物坊是 **Agent 产品工厂工作台**：围绕「一个产品项目」，用可编排的人机产线，把想法稳定做成**可本地运行的小应用**（MVP）；接近可上线是后续目标，不塞进本版必达。

## 2. 输入、过程与产物

### 2.1 输入
- 产品想法（一句话或短文）
- 可选：参考材料、已有 PRD 草稿、绑定的本地工作区目录（第一刀能力）
- 用户自备模型 API Key（工厂不垫付）

### 2.2 过程中人必须出现的点（人机边界）
以下三类 **必须人工完成**，Agent 不得自动跳过：

1. **决策**：改变方向、范围、成本、平台、数据隐私的选项（决策卡）
2. **确认**：PRD / 方案定稿确认后，才进入实现产线
3. **验收**：对「可本地运行」结果按清单勾选；未验收不得宣称交付完成

其余（检索、起草、生成代码、跑本地检查、整理产物）默认可自动，但高风险写盘/执行仍可要求确认（见第 8 节）。

### 2.3 产物（MVP）
- **产品项目**档案：想法、决策台账、PRD、Run 历史
- **可本地运行的小应用**：至少能在本机按说明启动，并完成主路径点选验证
- **运行说明**：如何启动、默认端口、验收步骤
- **验收记录**：人勾选的是否表

### 2.4 非目标（本版明确不做）
- 一键公网生产上线、企业认证代办、多租户商业化计费
- 「一天一款」作为硬指标（先实测再定）
- 整盘复制工作台的 Electron / Arco / Rust / IM 渠道全家桶
- 把证据包打分、工厂 KPI 作为 PM 主界面核心信息

## 3. Agent 主链路（工厂产线）

### 3.1 对象模型（对标工作台，Web 重做）

| 对象 | 含义 |
| --- | --- |
| **产品项目（Project）** | 一个要被造出来的产品；可绑定工作区目录；侧栏按项目聚合 |
| **产线 Run** | 项目下的一次制造尝试（可多轮迭代）；有阶段状态机 |
| **会话** | 人与工厂的对话容器；从属于某次 Run（或项目级澄清会话） |
| **产物 Artifact** | PRD、代码、说明、预览入口等；**一等公民**，进产物树与预览区，不只塞聊天气泡 |
| **闸门 Gate** | 人审点（决策 / 确认 / 验收）或自动检查点（语法、能否启动）；人审不可自动通过 |

### 3.2 阶段（MVP）

```text
想法录入 → 澄清提问 → 〔人：决策〕→ 起草 PRD → 〔人：确认 PRD〕
→ 实现生成 → 本地可运行检查 → 〔人：验收〕→ 交付归档
```

- 自动段失败：进入可理解失败态，保留原因与重试入口
- 确认 PRD 前：开发者可看过程细节；PM 默认只看问答与 PRD
- 确认 PRD 后：实现在绑定工作区落盘（若已绑定），并在预览区打开

### 3.3 工作台布局（必须三栏，视觉以整洁为先）

硬性约定：**桌面主区只有三栏**，不得再拆成四栏（禁止把「会话」与「编排」拆成并排两列）。

| 区域 | 职责 |
| --- | --- |
| **左栏** | 产品项目列表 / 某项目下的 Run 与会话；新建项目、搜索；角色切换（PM / 开发者） |
| **中栏** | **会话为主体**；顶部用一条紧凑进度条承载产线阶段；人审闸门（决策 / 确认 PRD / 验收）以内嵌卡片出现在对话流或中栏顶端，不另开一栏 |
| **右栏** | 产物树 + 预览 + 本地运行入口；PM 默认摘要/预览，开发者可看代码/日志/证据与工厂度量 |

学工作台的「会话 | 编排 | 预览/文件」心智：编排是中栏内的状态与闸门，不是第四列。实现用现有 Next + Tailwind，不搬 Arco。

#### 整洁度（本版起写入验收观感）
1. **少标签**：栏头一句职责即可，避免大段说明文案堆在栏内。  
2. **低密度**：空态一句话；进行中只突出当前阶段与下一步动作。  
3. **角色过滤**：PM 视图隐藏工厂内部阶段细节与度量；开发者可展开。  
4. **参考**：`product-manager-workbench` 的留白与信息层级，不追求像素级复刻。

### 3.4 可理解失败态（报错对人话）

自动段失败时，两个角色看到的信息不同：

| 角色 | 看到什么 |
| --- | --- |
| **PM** | 一句人话「哪一步没做成」+ 一句「怎么办」（建议动作）；**不出现** eval / subprocess / sandbox / 熔断 等技术词 |
| **开发者** | 技术原因（原始 failure_reason）+ 失败阶段 + 可看日志/证据；保留重测/整段重跑入口 |

失败分类 → PM 话术 + 建议动作（MVP 覆盖以下六类，未覆盖的进「其它」）：

1. **内容没通过安全检查**（用了不安全写法）→「生成的内容没过安全检查」→ 建议「换个说法再试」或「整段重跑」
2. **生成的代码有问题**（语法/结构/依赖缺）→「生成的代码跑不起来」→ 建议「整段重跑」
3. **主路径接口缺失**→「成品少了个必需接口」→ 建议「整段重跑」
4. **模型调用失败**（Key 或网络）→「模型没连上，多半是 Key 或网络问题」→ 建议「检查 Key 后重试」
5. **流水线卡死超时**→「这一步做太久，已被中断」→ 建议「整段重跑」
6. **其它 / 未知**→「这次没做成功」→ 建议「整段重跑」，并提示可切开发者看原因

**原则**：PM 视图永远给「人话 + 下一步」；技术细节只在开发者视图展开，不把底层报错直接甩给 PM。

## 4. 什么算「造得好」（验收标准）

### 4.1 MVP 成功定义（本版唯一硬标准）
一次 Run 在人工验收通过后，满足：

1. 有书面 PRD（人已确认）且与主路径一致  
2. 产物可在本机按说明启动（一条或少量命令）  
3. 验收清单主路径全部为「是」（由人勾选）  
4. 决策台账完整（关键决策均有人答）  

**不要求**：公网域名、生产级安全性、完整多租户、像素级设计完美。

### 4.2 质量判断
- PM：主路径是否符合想法、文案是否可懂、预览是否「像那么回事」
- 开发者：能否复现启动、代码是否在工作区可定位、失败日志是否可读
- 打分样例：2026-09-24 用 8 条真实想法打分——5 走通 / 2 半通 / 1 卡住（详见 `docs/PRD/版本/V1.1/验收证据/样例打分.md`）
- 判定「生成得好」：简单工具类（计算/点单/待办/起名/推荐/记账）应稳定走通；图像/视频类单独验证（当前不稳，待修）

### 4.3 后续（非本版必达）
接近可上线：部署脚本、账号隔离、监控与回滚等——单独立项，不挤占 MVP。

## 5. 交付阶段与优先级

### 5.1 第一刀（立刻做，对应工作台对标）
1. **项目 / 工作区绑定**：创建产品项目；可选附着本地目录；Run 按项目分组  
2. **产物一等公民**：右栏产物树 + 预览（PRD / 代码 / 运行说明）；结束「只靠聊天气泡交作业」  
3. **会话与产线分离 + 人审闸门**：中栏会话服务产线；决策 / 确认 / 验收三闸门强制人工  

### 5.2 第二刀（MVP 闭合）
- 本地可运行检查自动化（启动探测 + 主路径烟测或脚本）
- PM / 开发者视图切换（同一项目，信息密度不同）
- 失败可解释、可重试；取消 Run

### 5.3 第三刀（增强，可后置）
- 多模型对比工位、定时无人值守、多 Agent 分工看板  
- 接近可上线与桌面壳加强  
- 对外账号与商业化

## 6. 模型与成本

- 用户自备 Key；本地默认提供 mock 以便零成本走通产线
- 密钥不进仓库、不进前端、不在对话/日志/截图中回显
- 单次 Run 成本上限：待实测后写入状态台账；创建付费云资源前必须人确认

---

## 7. 数据与非功能

- 国内部署取向；业务数据默认不出境
- 项目、Run、决策、产物元数据持久化；进程重启可恢复
- 用户数据按登录账号隔离（已有手机号验证码登录可沿用；短信正式接入后置）
- 长任务需看门狗：无进度超时失败；等待人工确认不算卡死

---

## 8. 安全与权限

- 写工作区、执行安装/启动命令：默认可配置为需确认（开发者可「本 Run 始终允许」）
- 高风险 / 付费 / 对外发送：必须人确认，不交给模型自主
- PM 默认不能执行「危险调试」类动作；开发者角色可见

---

## 9. 界面与交互原则

- 对话式推进，但 **产物与预览不藏在长气泡里重复倾倒**
- PM 文案用产品语言；技术细节折叠到开发者视图
- 左项目 / 中会话 / 右产物；空态引导「新建产品项目」而非冷冰冰工厂术语
- 视觉：沿用现有浅色工作台方向，持续对标工作台的清晰分区，不复制其组件库

---

## 10. 与 V1.0 的关键差异

| 项 | V1.0 | V1.1 |
| --- | --- | --- |
| 成功标准 | 偏「完整可上线」 | **可本地运行的小应用**为 MVP 硬标准 |
| 角色 | 偏单一 PM | **PM + 开发者**双角色 |
| 工作区 | 任务列表 + 对话 | **项目 + Run + 产物树/预览**（工作台心智） |
| 人机边界 | 有确认，表述分散 | **决策 / 确认 / 验收**三人审点强制 |
| 对标 | 提到工作台外壳 | 明确学 IA/链路，**不搬** Electron/Arco/Rust |
| PM 界面 | 易暴露度量/证据 | PM 主路径隐藏工厂 KPI 与原始证据堆 |

## 11. 开放问题（写入状态台账，不阻塞 V1.1 开工）

1. 本地「可运行」的最低技术形态（例如固定 Next/FastAPI 模板 vs 随想法选型）——技术适配阶段定一套默认，不让 PM 选栈。  
2. 工作区目录权限文案与「始终允许」的默认策略。  
3. 第一批样例想法清单（用于校准验收与打分）。
