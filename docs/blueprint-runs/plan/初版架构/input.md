# Agent造物坊 · PRD（访谈稿 V0.1）

> 本稿由 2026-09 需求访谈整理，待产品经理确认后再进入阶段 0（PRD 体检）。
> 填不出来的项标"待定"，不脑补。

## 1. 目标用户与核心任务

- **目标用户**：任何非技术产品经理（终态为对外产品）。MVP 阶段先内部（产品经理本人 + 少数同事/朋友）验证跑通，再开放对外。
- **核心任务**：产品经理给一个想法，工厂用一套**可复用的 AI 约束流程**（阶段、闸门、证据包），稳定地把想法做成**可上线的 AI/Agent 产品**。
- **愿景**：先求可重复出货（稳定跑通第一款），再求"一天一款"（提效到极限）。

## 2. 输入、过程和产物

- **输入**：产品经理的想法/点子（一句话或 PRD 草稿）+ 产品经理的业务判断（回答"必须问"的问题）+ 产品经理自带的 API Key。
- **过程**：AI 按固定工序推进（拆需求 → 定架构 → 写代码 → 测试 → 上线），每个阶段有闸门卡住；产品经理在过程中看到进度、回答问题、查看证据。
- **产物**：完整可上线产品（前后端代码 + 部署 + 账号隔离），以及配套的 PRD、技术文档、验收证据包。
- **长期保留**：每个产品的 PRD、项目状态、决策台账、证据包，用于追溯和复用。

## 3. Agent 的主链路

- **多阶段分步流程**（沿用 AGENTS.md 的阶段闸门）：阶段 0 PRD 体检 → 阶段 1 技术适配 → 阶段 2 后端 MVP → 阶段 3 正式前端 → 阶段 4 上线 → 阶段 5 收尾。
- 每个阶段：AI 执行 → 闸门检查（十项是否表）→ 交付证据包 → 产品经理确认。
- **必须产品经理确认的节点**：回答"必须问"的业务问题、样例打分、高风险/付费/对外动作、阶段验收。
- **产品经理最小参与**：只回答问题（业务判断）+ 看证据 + 打分数，不做技术操作。

## 4. 什么算"生成得好"

- **总标准**：稳定出货——想法能走到"可上线产品"，全程通过闸门，不靠删测试、降标准、mock 冒充通过。
- **单款产品标准**（沿用 blueprint 六可）：可运行、可容错、可观测、可测试、可部署、可度量。
- **数字标准**：待样例打分——跑通第一款后用 5~10 条真实样例让产品经理打分，再据此定标准；时间口径（"一天一款"）也先实测第一款要多久再定。
- **允许的瑕疵**：待样例打分时一并确认。

## 5. 交付阶段与优先级

- **第一步（MVP）**：跑通"给想法 → 固定流程 AI 应用完整上线"这一条线（内部，产品经理本人 + 少数人验证）。
- **第二步**：套桌面外壳（像 product-manager-workbench 的形态）、扩展到自主 Agent 类产品。
- **第三步**：开放对外（账号、付费、多租户隔离）。
- **"一天一款"**：先不定死，跑通第一款后实测再定可达成版本。

## 6. 模型与成本约束

- **模型来源**：产品经理自带 API Key（工厂不垫钱、不代管统一模型、不做利润分成，起步阶段）。
- **密钥纪律**：密钥不进仓库、不进前端、不在对话/日志/截图/提交记录中回显。
- **成本上限**：待定（跑通第一款后实测单款成本再定）。

## 7. 数据与非功能要求

- **部署与数据**：全部数据与部署在国内、不出境。
- **多租户隔离**：每个产品经理的项目代码、密钥、数据彼此隔离（对外时强制，权限判断在后端）。
- **持久化**：业务数据、长任务状态、人工确认点必须持久化，进程重启后可恢复。
- **安全红线**：高风险/不可逆/涉及费用/对外的动作，由确定性代码 + 人工确认约束，不交给模型自主决定。

## 8. 上线与账号

- **登录方式**：手机号验证码。
- **云认证**：企业实名认证（耗时数天，阶段 0 起并行去办）。
- **上线节奏**：MVP 先内部试用；终态对外。
- **云费用预算**：待定。
